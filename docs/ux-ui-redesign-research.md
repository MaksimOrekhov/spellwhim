# Spellwhim — UX/UI-исследование и прототип «Сцена приключения»

> Статус: **исследование и изолированный прототип. Боевой интерфейс игры не заменён.** Правила, экономика маны, статусы, классы, `CampaignMap.vue` и `src/game/*` не изменялись. Основа: `origin/main` @ `d002085` (v0.8: Вариан, Джайна, «Уязвимость»). Ветка: `codex/ux-ui-redesign-exploration`.

## Как посмотреть прототип

```bash
npm run dev
# затем открыть  http://localhost:5173/ux-prototype.html
```

Справа сверху — свёрнутая панель «Прототип» (сценарии и экраны). Параметры адреса: `?s=normal|synergy|ten|swarm`, `&screen=battle|reward|map|victory|defeat`, `&hover=N` (показать увеличенную карту N), `&ui=0` (скрыть панель), `&reduce=1`. Играть можно по-настоящему: карты 1–9, 0 или клик, Enter — конец хода, наведение — увеличение карты и «свиток». Прототип подключён к **реальному движку** (`createCampaignBattle`, `previewCard`, `forecastEnemyAction`, `startCardPlay`/`resolveCardPlay`, `endTurn` — только чтение), поэтому все числа соответствуют v0.8; подменена лишь стартовая обстановка (рука, мана, здоровье, статус).

Текущую игру можно сравнить на соседней вкладке: `http://localhost:5173/`.

Скриншоты лежат в `docs/screenshots/ux-redesign/`, их воспроизводит `scripts/ux-redesign-shots.mjs` (инструкция — в шапке скрипта; `puppeteer-core` не является зависимостью проекта).

## 1. Аудит существующего интерфейса

Методика: чтение компонентов из задания, затем реальное прохождение боя (карта → бой → награда) на 1920×1080 и 1280×720; код сверялся с тем, что видно на экране. Снимки — `current-*.jpg`.

### 1.1. Что работает хорошо (сохранить)

| Что | Почему ценно |
|---|---|
| **Портреты Вариана и Джайны** | Самый сильный визуальный актив: яркие, узнаваемые, в едином стиле. Прототип использует их без изменений. |
| **Класс карты читается до текста** | Цвет рамки + орнамент (`angular`/`arcane`) + эмблема, цвета только в `classThemes.ts`. Это правильная архитектура для «значительно больше классов». |
| **Намерение врага — точный прогноз из движка** | `forecastEnemyAction` используется и правилами, и UI; видны броня, потери здоровья, «смертельно», подготовленная атака. Содержание прогноза хорошее — слабее его подача (п. 1.2). |
| **Предпросмотр урона** | `previewCard` считает бонусы теми же правилами; UI уже умеет подсвечивать готовый бонус. |
| **Фазовая машина и корреляция событий** | `useBattleAnimation` с ID действий, очисткой таймеров и тестами — надёжная основа; менять не нужно. |
| **Управление** | Клавиши 1–9, 0, Enter; карты — `button` с `aria-label`; фокус виден; `prefers-reduced-motion` учтён. |
| **Якоря Pixi** (`[data-fx-anchor]` в `[data-battle-scene]`) | Эффекты следуют за вёрсткой. Новый макет обязан сохранить этот протокол. |
| **Отдельный объект «класс/действие/состояние»** | `CARD_DESIGN_SYSTEM.md` разделяет три слоя карты — прототип следует ему буквально. |
| **Разметка в HTML/CSS, Pixi только для частиц** | Правильное разделение; сохраняется. |

### 1.2. Проблемы

Серьёзность: **Высокая** — мешает играть/читать; **Средняя** — ослабляет впечатление или ясность; **Низкая** — шероховатость.

#### Боевой UX

| № | Проблема | Серьёзность | Доказательство | Решение (проверено в прототипе) |

### 1.3. Что ограничивает, но не является ошибкой

* Круглые портреты — осознанное решение для текущих ассетов; арки в прототипе показывают, что те же файлы работают и в другой форме (квадрат 768×768 с лицом в центре кадрируется удачно).
* Тёмно-бирюзовый фон — подходит для «Сумеречной чащи»; проблема не в цвете, а в том, что хром привязан к нему. Для Мёртвых копей хром должен остаться прежним.

## 2. Сильные стороны, которые нужно сохранить

Сводка из 1.1 как «нельзя ломать»: (1) портреты и их узнаваемость; (2) классовая идентичность через `classThemes.ts`; (3) точный прогноз врага и предпросмотр урона из движка; (4) фазовая машина `useBattleAnimation` и корреляция ID; (5) клавиатурное управление и reduced-motion; (6) якоря Pixi; (7) разделение «HTML/CSS — интерфейс, Pixi — частицы»; (8) принцип «карта — не перетаскивание, а нажатие».

## 3. Конкретные UX-проблемы (приоритетный список)

1. **U1 + U2 — читаемость руки** (имена, правила, перекрытие на 720p). Главное, что стоит чинить первым.
2. **U3 — мана.**
3. **U4 + U5 — угроза и Уязвимость** должны читаться «на теле» героя/врага, а не в таблице.
4. **U6, U10 — масштаб:** герои и рука слишком малы относительно экрана.
5. **V1–V3 — цельность:** фон, материалы, единый язык всех экранов.
6. **U7–U9 — доступность карт, свиток, конец хода.**
7. **V5–V7 — шрифты, токены, запечённый круг врага.**

## 4. Анализ референсов

> Источник — общее знание о перечисленных играх (интерфейсы хорошо известны), **не** свежая съёмка в рамках сессии. Цель — принципы, а не копирование HUD/рамок (по `ART_BIBLE.md` запрещено переносить рамки и интерфейс Hearthstone).

| Игра | Что делает хорошо | Применимо к Spellwhim |
|---|---|---|
| **Hearthstone** | Поле — «диорама» с материальными рамками; рука лежит веером и **увеличивается при наведении**; бонусы (сила заклинаний) окрашивают числа на карте; ключевые слова — коротко, объяснение — боковой подсказкой; кристаллы маны — главный индикатор; сильная «тактильность» (подъём, звук, вспышки, анимации ударов). | Увеличение + боковой свиток; золотые числа при бонусе; мана как крупный объект; короткие ключевые слова. **Не копировать:** форму рамок и HUD. |
| **Slay the Spire** | Намерение врага — над головой врага, иконка + число; статусы — иконки с числами; энергия — крупный шар; карты — крупное арт-окно и мало текста; карта пути — иконки узлов и подсвеченный путь. | Намерение — иконка + число + цель; шар маны; карта шахты как граф с иконками. |
| **Monster Train** | Очень крупные юниты; урон и здоровье читаются мгновенно крупными числами; подсказки по статусам при наведении, но иконок мало и они разные; эффекты короткие. | Крупные числа, плашки статусов-«медальонов». |
| **Across the Obelisk** | Партия героев внизу, враги вверху, у карт цвет по классу; боковая панель ключевых слов около увеличенной карты; плотная, но структурированная информация. | Боковой свиток; цвет класса; партия как единая группа. |
| **Roguebook** | Два героя с общей рукой; карта-«книга» — материальный носитель карты; цвет карты — по герою. | Пара героев с общей рукой — прямая аналогия; чертёж шахты как «носитель». |
| **Wildfrost** | Очень «осязаемый» интерфейс: счётчики на юнитах, пухлые формы, выразительные реакции на действия; минимальный шум. | Реакции портретов (тряска, вспышка); крупные счётчики; мало текста. |
| **Griftlands / Hades (по необходимости)** | Герои не «в аватарках», а в сцене; события — иллюстрированный диалог. | Для событий/привалов (раздел 9). |

### Выводы для Spellwhim

1. **Одна и та же информация — в трёх слоях:** сцена (цвет, свечение, луч) → цифра → текст-подсказка. Игрок берёт столько слоёв, сколько нужно.
2. **Карта в руке — «обложка», подробности — по запросу.** Текст в 3 строки не выживает на 130 px; числа и иконки — выживают.
3. **Ключевое слово = иконка + одно слово + определение в свитке.** «Уязвимость» не пересказывается на каждой карте.
4. **Угроза и цель связываются визуально** (линия/свечение), а не по имени в тексте.
5. **Мана — главный объект HUD**, наравне с рукой.
6. **Действия короткие и осязаемые:** подъём карты, полёт, вспышка, число. Всё остальное — за пределами 1 секунды.
7. **Один язык материалов на всех экранах** (карта, награда, события, привал) — главное, чего нет сейчас.

## 5. Три альтернативные визуальные концепции

### A. Fantasy Tabletop — «Походный стол»

* **Идея.** Дорогая настольная игра: бой разыгрывается на столе-картe; фигуры — фишки на латунных подставках; карты — толстые, с тиснением.
* **Композиция.** Вид «сверху под углом»: стол с рамой из дерева, пергаментное игровое поле, фишки героев и врага на подставках, карты в руке у нижнего края стола, жетоны маны и здоровья — отдельные объёмные предметы.
* **Палитра.** Тёплое дерево `#3d2a1b`, латунь `#d2a24f`, пергамент `#f1e2bd`, цветные «камни» (мана — сапфир, здоровье — рубин).
* **Панели и карты.** Объёмные, с заклёпками и швами; карты — прямоугольники с толстым бортом.
* **Типографика.** Засечки с характером (Alegreya SC / Cormorant SC), цифры на жетонах — моноширинный «чеканный» гротеск.
* **Персонажи.** **Фишки-стойки** (standee) — вырезанные портреты на подставке. Потребует вырезанных силуэтов: имеющиеся портреты — квадраты с фоном.
* **Анимация.** Фишки «ставятся» на поле, жетоны щёлкают, карты шлёпаются.
* **Читаемость.** + Очень структурно, каждый ресурс — предмет. − Много «вещей» = много шума; персонажи мельче; стол отнимает площадь.
* **Стоимость.** Высокая: текстуры, вырезанные персонажи, отдельный арт для каждой локации-стола.

### B. Warcraft Adventure — «Сцена приключения»

* **Идея.** Кинематографичная сцена: локация во весь экран, герои и враг — крупные «фигуры» в сцене, HUD уходит к краям, информация переезжает **на самих персонажей**.
* **Композиция.** Треугольник: враг по центру сверху, герои по бокам ниже, платформа-дайс между ними; рука — веером по низу; мана и конец хода — по углам.
* **Палитра.** Яркая локация (чаща — изумруд/золото/фиолет; шахты — охра/медь/синий холод) + **постоянный тёплый хром** (дерево/латунь) и пергамент.
* **Панели и карты.** Минимум панелей: полосы здоровья-«пластины» под портретами, баннер намерения, шар маны; рамки карт — по классу (металл / ночное небо).
* **Типографика.** Засечки для названий, крупные «чеканные» цифры для чисел, мелкий гротеск для служебного.
* **Персонажи.** Крупные арки (герои) и медальон (враг) — используют имеющиеся портреты; позже — полноростовые/полу-фигуры.
* **Анимация.** Реакции персонажей (тряска, вспышка), лучи угрозы, снятие/наложение статусов на теле, полёт карты.
* **Читаемость.** + Максимальная: цвет/число/текст на самом объекте. − Требует хорошего фона и аккуратного баланса «сцена против интерфейса».
* **Стоимость.** Средняя: основные затраты — фоны локаций (по одному на биом) и согласование эффектов Pixi с новой раскладкой.

### C. Modern Stylized Card Game — «Чистый кристалл»

* **Идея.** Современный чистый интерфейс: плоские формы, крупные акценты, много воздуха; фэнтези — через цвет и иконки, а не текстуры.
* **Композиция.** Строгая сетка: враг сверху, герои снизу, карты — ровная полоса; ресурсы — компактные чипы.
* **Палитра.** Тёмная нейтральная основа + 3–4 насыщенных акцента (мана — циан, угроза — красный, бонус — золото).
* **Панели и карты.** Плоские, скруглённые, с цветной «пилюлей» класса и крупной иконкой действия.
* **Типографика.** Один современный гротеск, цифры — табличные.
* **Персонажи.** Круглые/квадратные аватары (как сейчас).
* **Анимация.** Быстрые ease-out, акцент на числах.
* **Читаемость.** + Лучшая на минимальном размере и самая простая в поддержке; − слабая идентичность «Warcraft/hand-painted», **спорит с `ART_BIBLE.md`** (там — «яркая живописная фактура, насыщенный свет»), легко выглядит как «любой веб-интерфейс» — а именно это сейчас и проблема.
* **Стоимость.** Низкая.

|---|---|---|---|
| Ощущение «законченной игры» | Высокое | **Высокое** | Среднее |

## 6. Выбранное направление и обоснование

**Выбор: B «Сцена приключения» с материалами из A на уровне HUD и карт** (латунь, дерево, пергамент — только там, где игрок «берёт предмет в руки»: карты, мана, кнопка, свиток).

Почему:

1. **Решает главную проблему, а не только окраску.** Информация о боевой ситуации переезжает с боковых панелей на самих персонажей (свечение угрозы, плашка потери, прицел Уязвимости, луч намерения). Это изменение композиции, а не палитры.
2. **Использует уже имеющееся лучшее** — портреты — и не требует нового арта для проверки идеи (прототип собран из текущих файлов и SVG).
3. **Согласуется с `ART_BIBLE.md`**: яркая живопись, насыщенный свет, «спокойные зоны» под HUD; материалы HUD нейтральны к локации, поэтому один и тот же хром переживёт переезд из Сумеречной чащи в Мёртвые копи.
4. **Масштабируется на классы:** класс карты задаётся тремя токенами и одним «орнаментом» (`classThemes.ts`), чипы и строки правил выводятся из данных (`effects`), а не пишутся вручную.
5. **Умеренная цена:** большая часть — CSS/SVG и небольшие компоненты; дорогой арт (фоны) можно подключать независимо.

**Что взято у A:** латунь/дерево/пергамент, шар маны, «свиток». **Что отклонено:** фишки-стойки (нет вырезанных персонажей), стол (съедает площадь). **Что взято у C:** дисциплина «меньше текста — больше чисел», табличные цифры.

## 8. Предложения по картам, HUD, состояниям и анимациям

### 8.1. Карта (центральный элемент)

**Размеры и пропорции.** 11.6 × 17 em; на 1080p это 186 × 272 px (≈ 0.68). Сейчас ≈ 130 × 290 (≈ 0.45) — слишком узкая. На компактных экранах `--card-scale: .95`. Масштаб — через `em` на корне карты (награда = `font-size: 1.5rem` без перерасчёта вёрстки).

**Анатомия (сверху вниз).**

1. **Кристалл стоимости** — общий для всех классов (синий = мана, как в `CARD_DESIGN_SYSTEM.md`), выступает за рамку, красный и «серый» при нехватке маны.
2. **Арт-окно** 7.6 em (≈ 45 % высоты). На нём: эмблема класса (справа сверху), «наклейка» статуса (слева, после кристалла), плашка «нужно N · есть M».
3. **Лента названия** перекрывает нижний край арта; форма по классу (Воин — лента с вырезами-«ласточкиными хвостами», Маг — «пилюля»). `v-fit-text` сохранён; в плотной руке название выравнивается влево и ужимается **под видимую часть**.
4. **Чипы эффекта** (≤ 2): значок в цветном диске + число + подпись («врагу», «цели», «напарнику», «Джайне», «карты»). Один чип увеличивается (`is-solo`).
5. **≤ 2 короткие строки** условий: «+2 при броне Джайны» (серая — условие не выполнено; золотая «+2 — броня Джайны» — выполнено), «Урон, если враг атакует», «Выбывает до конца боя».
6. **Подвал:** клавиша (слева, чтобы не пряталась под соседней картой) и название класса.

**Данные → интерфейс (`cardGlyphs.ts`).** Чипы и строки выводятся из `effects`/`damageBonus`/`exhaust` и `CardPreview` — без текста вручную. Новая карта почти всегда не требует кода UI. Правило: **не более двух числовых чипов; статусы — наклейкой**; если у будущей карты три числа — добавить компактный ряд, а не удлинять карту.

**Короткие ключевые слова.** «Уязвим» — значок-прицел + слово; определение — только в «свитке» (из `statusDefinitions`). Следующие кандидаты на тот же механизм: «Выбывает», «Добор». Точность правил сохраняется: полный текст `card.description` дословно присутствует в «свитке» и в `aria-label`.

**Предпросмотр итогового урона.** Чип урона показывает **итоговое** число (из `previewCard`): золото + свечение при бонусе; серое «+2 при броне Джайны» — «потенциал» синергии (учит новичка). В «свитке» — разложение и эффект на врага (броня/здоровье). При наведении на врага — призрачный сегмент потери на полосе здоровья; при наведении на защитную карту — «призрачная» броня на герое, которого она прикроет.

**Подсветка активных бонусов.** Золотая рамка + мягкое свечение всей карты + пульс чипа; золото закреплено за «бонус/синергия» на всех экранах (одно значение — один цвет).

**Наведение.** Подъём и увеличение ×1.3 за 0.24 с, `z-index` выше соседей, соседи не сдвигаются (сдвиг выталкивал последнюю карту под кнопку конца хода — это выявлено в ходе прототипирования), «свиток» открывается в свободную сторону. Фокус клавиатурой даёт то же самое.

**Недоступные карты.** Арт и чипы обесцвечены и затемнены, кристалл стоимости серый с красным числом, плашка «нужно 2 · есть 1» на арте, карта чуть опущена. Класс по рамке остаётся читаемым (требование `CARD_DESIGN_SYSTEM.md`).

**Рука 8–10 карт.** Раскладка вычисляется по ширине: без перекрытия, пока помещается; иначе шаг уменьшается, карта получает «видимую долю» `vis`, и ниже 0.86 включается **плотный режим** (подписи чипов скрыты, название ужато под видимую часть). Критичное (стоимость, имя, главное число, клавиша) лежит в левой части карты, поэтому переживает перекрытие 27 % (10 карт на 1080p). Веер ±1.35° на карту — только для «живости».

**Будущие классы.** Класс = `classThemes.ts` (3 цвета + эмблема + `ornament`). Нужно будет добавить *варианты орнамента* (сейчас `angular`/`arcane`; следующие — например `wild`, `holy`), каждый — 10–15 строк CSS для рамки/ленты. Чипы, строки, свиток, награда — не меняются.

| Победа/поражение | Лента-баннер поверх приглушённой сцены (не диалог). |

### 8.4. Анимации и обратная связь

Принципы: **коротко (≤ 0.5 с на элемент), по делу (источник → цель → результат), без блокировки сверх необходимого, всё отключается `prefers-reduced-motion` и переключателем.** Текущие тайминги `useBattleAnimation`: попадание 560/820 мс, завершение 880/1120/1300 мс. Прототип укладывается в 0.76 с на розыгрыш и 0.9 с на ход врага (плюс 1.25 с баннера, не блокирующего ввод).

| Событие | Предложение | Слой | Длительность |
|---|---|---|---|
| Наведение на карту | подъём+масштаб ×1.3, свиток | CSS | 0.24 с |
| Розыгрыш | карта летит к цели, уменьшаясь и поворачиваясь | CSS (прототип) → **Pixi-снаряд** для заклинаний (как сейчас) | 0.34 с |
| Попадание | вспышка, тряска цели, число урона, «−N брони» отдельно | Pixi (`popAt`) / CSS | 0.45–0.6 с |
| Появление брони | вспышка на прикрываемом герое, значок щита «выскакивает» с `+N`, «призрачная» броня при наведении | CSS | 0.9 с |
| Наложение Уязвимости | перекрестие «вжимается» на враге (`scale .4 → 1`) + «Уязвим!» | CSS | 0.45 с |
| Снятие Уязвимости | золотая надпись «Уязвимость снята · +3», перекрестие гаснет | CSS | 0.9 с |
| Получение урона | тряска портрета, «−N» над героем, полоска здоровья плавно | CSS | 0.45 с |
| Переключение ходов | лента меняет цвет; баннер-проход 1.25 с | CSS | не блокирует |
| Смена фазы босса | вспышка яркости + смена рамки; лента «Фаза II» | CSS | 0.65 с (есть сейчас) |
| Добор | карты «въезжают» слева (из колоды) | CSS (`TransitionGroup`) | 0.45 с |
| Награда | карты поднимаются со сдвигом по очереди (0.09 с) | CSS | 0.55 с |
| Переход в комнату | вагонетка едет по ребру карты | CSS/SVG | 0.6 с |

**Быстрая игра.** Нужна возможность разыгрывать несколько карт подряд: (1) режим «быстро» (прототип: ×0.5 ко всем задержкам); (2) при внедрении — **буфер ввода** одного следующего действия на время анимации, чтобы нажатия не терялись (требует аккуратной работы с `useBattleAnimation`: сейчас `play` отбрасывается при `busy`; тесты на устаревшие ID должны остаться зелёными). Это единственная часть исследования, которая трогает логику анимаций, поэтому в плане она выделена отдельным этапом.

**Pixi.** `BattleFx.vue` уже умеет: росчерк меча, огненный шар, защиту, подготовку, всплывающие числа — по якорям `[data-fx-anchor]`. Новая раскладка сохраняет эти якоря (в прототипе они проставлены: `data-fx-anchor="warrior|mage|enemy"` внутри `[data-battle-scene]`). При внедрении потребуется только: перекрасить частицы под токены (мана, угроза, бонус), поправить размеры шрифта чисел (`Georgia` → токен), и использовать «центр» арки/медальона.

## 9. Принципы единого дизайна будущих экранов

### 9.1. Язык

1. **Один набор материалов** на всех экранах: латунь (рамки, кнопки), тёмное дерево (панели), пергамент (текст для чтения), «камни» (ресурсы). Локация меняет только фон.
2. **Один смысл — один цвет:** мана — циан, здоровье — рубин, броня — сталь, угроза — оранжево-красный, бонус/синергия — золото, Уязвимость — янтарь. Класс — только цвет класса.
3. **Три уровня информации:** сцена (свет/цвет) → число → текст по запросу.
4. **Две формы кнопок:** «табличка» (главное действие: конец хода, взять карту, продолжить) и «пилюля» (вторичное: справка, пропустить).
5. **Две формы персонажей:** арка = мы, круг-медальон = они; события/NPC — овальный портрет в рамке-свитке.
6. **Лента вместо диалога** для сообщений-событий (победа, поражение, новая фаза).
7. **Анимации входа:** снизу-вверх со сдвигом 0.09 с; выход — быстро.

### 9.2. Карта подземелья «Штреки» (эскиз для Dungeon Map Foundation)

Учтена рекомендация `docs/roguelike-adventure-design-research.md` (ветка `codex/roguelike-adventure-design-research`, §5.4): слоистый граф, 3 колонки, 8 горизонтов + босс, именованные области, иконки узлов, рельсы, вагонетка. **`CampaignMap.vue` не трогался**; `ProtoMap.vue` — статическая схема с ручными данными (не генератор).

![Чертёж шахты](screenshots/ux-redesign/proto-1920-map.jpg)

Идея композиции: «штрек» — горизонтальная выработка, поэтому три **штрека идут слева направо** (16:9 использует ширину лучше, чем вертикальный стебель Slay the Spire), горизонты — вертикальные крепи с фонарями, развилки — рельсовые ходы между штреками, область («Забой», «Мастерская и литейная», «Железный борт») — табличка сверху. Узел — круглая «бирка» с иконкой и цветом типа; пройденные — тускнеют, достижимые — пульсируют, текущий — с вагонеткой; рельсы выбранного пути золотятся; снизу — свиток с описанием узла под курсором, легенда и состояние отряда.

Для разработки генератора важно: узлы — HTML-кнопки (фокус/клавиатура), рёбра — SVG-кривые, позиции вычисляются из `(слой, дорожка)`; тип узла → `{иконка, цвет, название, подсказка}` — данные, а не код. Компонентам не нужно знать, как построен маршрут.

### 9.3. Привал, событие, кузница, торговец, награда (схемы)

Общая раскладка «сцена + свиток»: фон биома, 1–2 портрета, пергаментный свиток с выбором, кнопки-таблички.

```text
СОБЫТИЕ («?»)                              ПРИВАЛ («R»)
┌──────────────────────────────────┐       ┌──────────────────────────────────┐
│ фон: локация, затемнён 28 %      │       │ фон: костёр в штреке             │
│  ┌────┐   ┌──────────────────┐   │       │  ┌────┐  огонь  ┌────┐           │
│  │овал│   │ СВИТОК           │   │       │  │Вар.│ ░░░░░░  │Джа.│           │
│  │NPC │   │ Заголовок        │   │       │  │ 25 │         │ 12 │           │
│  └────┘   │ текст 3–4 строки │   │       │  └────┘         └────┘           │
│           │ ┌──────────────┐ │   │       │  ┌───────────┐ ┌───────────┐     │
│  ┌──┐┌──┐ │ │ Вариан: …    │ │   │       │  │ Отдохнуть │ │ Улучшить  │     │
│  │В ││Д │ │ │ Джайна: …    │ │   │       │  │ +13 HP    │ │ карту     │     │
│  └──┘└──┘ │ │ Отказаться   │ │   │       │  │ (кому?)   │ │           │     │
│  подходы  │ └──────────────┘ │   │       │  └───────────┘ └───────────┘     │
│           └──────────────────┘   │       │ отряд: ♥ 25/25 · ♥ 12/18         │
└──────────────────────────────────┘       └──────────────────────────────────┘
```

* **Подходы героев** (идея из исследования приключения) — две «плашки-подхода» с портретами в аркe-миниатюре: игрок видит, **кто** предлагает вариант.
* **Распределение лечения** — два ползунка в арках героев (лечение «кому»), а не меню.
* **Награда** — как реализовано в прототипе; «Пропустить» — пилюля.
* **Торговец** — свиток-прайс слева, три карты справа в том же размере, что и награда.

## 12. Что не стоит менять и почему

| Что | Почему |
|---|---|
| **Движок, правила, экономика маны, статусы, классы** | Не входит в задачу; результаты Balance Lab завязаны на правила. Прототип только читает движок. |
| **`useBattleAnimation` (фазы, ID действий, очистка таймеров)** | Надёжная и протестированная корреляция; менять только на этапе 6 и с тестами. |
| **Протокол якорей `data-fx-anchor` в `data-battle-scene`** | Единственный контракт между вёрсткой и Pixi; новый макет его сохраняет. |
| **Разделение HTML/CSS (интерфейс) и Pixi (частицы)** | Правильное; прототип его не нарушает. |
| **`classThemes.ts` как единственный источник цветов классов** | Позволяет добавлять классы без правки компонентов. Прототип берёт цвета оттуда (`classThemeStyle`). |
| **Нажатие вместо перетаскивания карт** | Правило `AGENTS.md`; перетаскивание ухудшает клавиатурную и компактную игру. |
| **Клавиши 1–9, 0, Enter и `aria-label`** | Доступность и скорость; прототип сохраняет, дополнительно переносит клавишу в левую часть карты. |
| **Портреты Вариана и Джайны** | Лучший актив; не пересоздавать до проверки на живом кадрировании. |
| **Круглый портрет врага до появления нового арта** | Запечённая маска (V7). |
| **Тексты правил карт** | Это зона дизайна правил; UI лишь сжимает отображение и показывает полный текст в свитке. Замечание T1 передано как наблюдение. |
| **`CampaignMap.vue` и маршруты** | Параллельная работа (Dungeon Map Foundation); визуальное направление дано отдельной схемой. |
| **Тёмно-бирюзовая палитра «Сумеречной чащи» как цвет локации** | Нормальна как фон; менять нужно привязку хрома к ней, а не сам биом. |
