# Combat UI Clarity v0.1

UX-итерация поверх Combat Overhaul v0.2 (ветка `claude/combat-overhaul-v02`). Правила, числа врагов, экономика, карты, статусы, артефакты, награды, боты и генерация карты **не менялись**. Отчёт Combat Overhaul (`combat-overhaul-v02.md`) описывает интерфейс как он был в том этапе и не переписан.

## 1. Почему прежний интерфейс был перегружен

Одно и то же намерение сообщалось пять раз: текстовый баннер («Сейчас без урона — удар на следующем ходу»), аватар с `−13` в баннере, плашка над аркой героя («Следом −13 HP · 13 урона · броня −4»), `−13` внутри полосы здоровья и красная надпись «Смертельно». Плюс мигающая рамка, вращающийся прицел, мигающая полоса. Подготовка показывала точный будущий удар и одновременно говорила «сейчас без урона» — отсюда противоречие.

## 2. Что убрано или упрощено

| Было | Стало |
|---|---|
| Баннер: надпись типа, название, пояснение, аватары, числа | Иконка действия + число на цель (+ щит поглощённого). Название и расчёт — в подсказке |
| Плашка над аркой: «Под ударом −13 HP · 13 урона · броня» | Один круглый маркер без числа (прицел / щит / череп / песочные часы) и цвет рамки |
| Число `−N` в тексте полосы здоровья | Только «призрачный» сегмент (число — в баннере) |
| Надпись «Смертельно» (мигала) | Череп на маркере и в баннере, глубоко-красная рамка и свечение |
| Бирка «Фаза II» в баннере | Остаётся только значок фазы на медальоне врага |
| Мигание рамки, вращение прицела, мигание призрака, мигание «смертельно» | Нет постоянных анимаций; остаётся короткое появление числа и бегущий пунктир луча |
| Статус: пилюля «иконка + название + число» | Иконка одного размера + одно число; название и пояснение в подсказке |

## 3. Итоговая система намерений

Принцип: **на портрете героя — состояние героя и маркер угрозы; возле врага — действие врага; подробности — в подсказке.** Для каждого героя число показано один раз (в баннере), полоса здоровья показывает ту же потерю сегментом.

| Действие | Баннер |
|---|---|
| `attack` | меч · потеря здоровья цели; щит `4` рядом, если броня поглотила часть; щит-галочка вместо числа, если удар поглощён целиком |
| `attack_all` | скрещённые мечи · два чипа «лицо героя + число»: у героев потери разные (броня, артефакты), единого числа нет |
| `prepare` | песочные часы · лицо цели (лица обеих при массовой) · `?` ; пунктирная рамка |
| `defend` | щит · `+броня` |
| `recover` | щит-плюс · `+броня` |

Число — это здоровье, которое герой потеряет на самом деле (после брони, статусов и артефактов). Полный разбор «удар 12, броня поглощает 4, здоровье −8» — только в подсказке.

На героях: горячая рамка и прицел — удар сейчас; стальная рамка и щит — удар поглощён; красная рамка с черепом — смертельно; пунктирная янтарная рамка и песочные часы — подготовка. Лучи сохранены (пунктир при подготовке).

## 4. Скрытие урона при подготовке

Движок по-прежнему считает всё: `forecastEnemyAction` отдаёт и `futureTargets` с точными числами подготовленного удара, на них опираются тесты, симуляции и бот. Но сцена **никогда не получает прогноз**. `BattleBoard` превращает его в `PublicIntent` (`src/ui/threatDisplay.ts`), и дальше вниз идёт только он:

- вариант `prepare` не имеет числовых полей: `{ kind, name, phase, targets, blow }`;
- метки героев — `{ when: 'prepared', hero }` без чисел; лучи, призрак на полосе и `lethal` строятся только из раскрытых ударов;
- все тексты (aria-label баннера и героя, подсказка) генерируются функциями той же модели, поэтому в них попасть скрытому числу неоткуда;
- `BattleFx` получает только `incomingLoss` — потери раскрытых ударов;
- утечка превращается в ошибку типов, а тест-страж запрещает компонентам упоминать `futureTargets`/`EnemyActionForecast`.

Последовательность: подготовка (цель известна, размер `?`) → удар объявлен (точное число, предупреждение о смертельном) → ход игрока → исполнение. «Готовый» удар — обычный `attack`, рисуется так же; смену подчёркивает короткое «вспыхивание» числа.

## 5. Статусы

Один формат для любого числа статусов: квадрат со скруглением одного размера, иконка Lucide/существующий ассет, **одно число** (`badge` в `StatusView`, берётся из определения: `+3` для Уязвимости по `hitBonus`, сила для Кровотечения). Стойка у портрета слева-внизу — у врага и героев одинаковая. Полярность не только цветом: стрелка в углу (вниз — вредит носителю, вверх — помогает). Подсказка: название и одно описание из определения (без дубля правил во Vue). Кровотечение также рисует золотой призрачный сегмент на полосе врага.

## 6. Два варианта оформления

Оба построены из одних и тех же компонентов; вторая раскладка включается `?intent=caption` в лаборатории (`card-preview.html`).

| Критерий | A. Минимализм (иконка + число + лицо) | B. Та же, с названием действия |
|---|---|---|
| Читаемость с первого взгляда | лучше: всё одного размера, одно действие — один знак | чуть хуже, взгляд цепляется за строку |
| Количество текста | ноль | одна короткая строка |
| Подготовка | часы + `?` понятно из контраста с мечом | то же + название («Берёт Джайну на прицел») |
| Массовая атака | компактно | баннер шире |
| Статусы / развитие | не зависит от названий; длинные имена не ломают раскладку | длинные названия растягивают баннер |
| Новичок | нужно один раз навести курсор | название помогает, но дублирует смысл иконки |

**Выбрано A.** Название — это прикраска, а не информация для решения; оно есть в подсказке и озвучивается. Если playtest покажет, что новичкам не хватает названия, вариант B включается одним пропом (`captioned`).

## 7. Дымовая завеса — спецификация (не реализована)

1. **Механика.** Особое действие конкретных врагов (гоблин с дымовой шашкой), не поведение по умолчанию: враг выполняет `smoke`, и на один свой ход (следующее объявленное действие) намерение становится скрытым.
2. **Что остаётся.** Факт «намерение скрыто», счётчик ходов до раскрытия, список способностей врага (по иконкам известно, что он умеет скрывать), здоровье/броня/статусы врага. Скрыты тип действия, урон и цель.
3. **Понятность.** Вместо иконки — облако дыма и `?` (отличное от песочных часов: те обещают раскрытие); пунктирные лучи на оба героя; подсказка «Враг скрывает намерение на 1 ход». У врага на медальоне постоянный значок «Любит дымовые шашки» до первого боя с ним.
4. **Раскрытие.** Автоматически в начале следующего хода игрока: после одного скрытого хода объявляется следующее действие обычным образом.
5. **С подготовкой.** Подготовка внутри дыма остаётся подготовкой, но скрыт и тип; раскрытое «готовое» действие после дыма показывается как обычно. Дым не может скрыть уже раскрытый точный удар — только следующее объявление. Дым и подготовка не подряд.
6. **Честность.** Дым не накладывается на смертельный ход, если у отряда нет возможности защититься (проверка сценарием: худший скрытый удар ≤ суммарному здоровью + 1 защитная карта в руке); скрытое действие не сильнее максимального объявленного у этого врага; не чаще раза за цикл; всегда есть сигнал заранее («Готовит дым»); можно сыграть защиту на оба героя.
7. **Интерфейс.** Баннер той же формы, иконка дыма, `?` вместо чисел, без ложных чисел и без черепа; расчёт и подсказка — без утечек; публичная модель получит ещё один вариант `{ kind: 'hidden', turnsLeft }` — та же защита типов.

## 9. Проверки

- `npm test` — 17 файлов, 259 тестов, включая новые: подготовка не содержит чисел в модели, тексте, подсказке, aria, серверном рендере (рендер с другим скрытым уроном идентичен); раскрытие точное; цель; два героя с разной бронёй; смерть только для текущего удара; броня; бейджи статусов; прогноз совпадает с реальной потерей здоровья во всех сценах; рендер не меняет состояние.
- `npm run build` — успешно.
- `npm run balance:smoke`, `npm run scenarios -- 42`, `npm run dungeon:routes -- 42 100` — вывод до и после идентичен (различаются только колонки времени выполнения в мс). Эталон 427 боёв проходит.

### Найдено, не исправлено (ботам разрешено то, что скрыто от игрока)

`balance.ts:156` (`forecast.targets.length ? forecast.targets : forecast.futureTargets`) и `scenarios.ts:62` читают точный урон подготовленного удара. Бот-планировщик видит то, чего не видит игрок, поэтому цифры балансных ботов при подготовке слегка оптимистичны. Менять нельзя без пересмотра отчётов; вынесено в отдельную задачу.

## 10. Остающиеся проблемы

- Название действия видно только в подсказке; нужно проверить на новичках.
- Череп в баннере мелкий при 1280; основной сигнал — маркер на портрете.
- Подсказки статусов не показывают текущее значение словами (число на иконке).
- Рука из 10 карт на узком окне 900 остаётся тесной (вне задачи).
- Движение анимации исполнения (`exec`) осталось; постоянных миганий нет.
