19.10.2026. План, не начатая реализация. Основной дизайн — [GDD](spellwhim-gdd-v2.md), измерения — [Experimental Plan](spellwhim-gdd-v2-experiments.md). Каждая строка — самостоятельная задача с отдельными diff/проверками/решением. Этапы не означают автоматическое принятие всех чисел PROTOTYPE.

Почему порядок отличается от старых roadmap: сохранение и постоянные копии объединены **раньше** генератора, а не этапом после длинного похода. Золотые вводятся после улучшений, поскольку иначе тест элит сравнивал бы единственный скачок силы с его отсутствием. Совместность — один небольшой общий контракт в этапе 4, а не девять новых кирпичиков одновременно.

Допустим параллельный **дизайн данных/арта после утверждения**, но это не авторизация отправлять задачи другим агентам. Кодовые зависимости этапов остаются: готовый текст события не заменяет рабочую транзакцию, готовый портрет — корректное действие врага.

У каждого этапа исполнитель сначала читает код, выбирает конкретную архитектуру, сохраняет legacy API/контроли по необходимости и завершает проверки. После прохождения gate обновляются GDD/Decision Log и матрица EXISTING/PLANNED. Балансные параметры, получившие новые данные, не объявляются согласованными без соответствующего решения владельца.

Сроки по дням не оценены: объём UI/хранилища/совместимости определяется инженерным разбором. Границы этапов важнее искусственного обещания реализовать «по одному статусу за день».
