# GDD v2.0 — Experimental Plan

План к [GDD](spellwhim-gdd-v2.md), 19.10.2026. Числовые пороги ниже **PROTOTYPE критериев**, не принятые балансные константы. Список не разрешает реализацию в документационной ветке.

Общий протокол: фиксировать версию кода/каталога/конфигурации, seed всех подсистем, точные копии/улучшения, public-информацию, бота/лимиты/профиль драфта, timeout и исключения. Контрольные aggressive/defensive/balanced не перенастраивать под результат. Planner — дополнительный ограниченный горизонт, не оптимальная политика. Основной и независимый диапазоны seed задаются **до** настройки; после выбора не перетюнивать по holdout. Для небольших разниц нужны парные исходы/интервалы, а не округлённые средние из разных ростеров.

Сохранять проигрыши и ранние остановки. Средние late-battle/HP среди дошедших несут selection bias; вместе показывать число дошедших, checkpoint по фиксированным встречам и survival curves. Не заполнять пустое среднее «0 HP потеряно». Случайный переход по ребру — не человеческий выбор и не равномерная выборка полных путей.

## E01 — размер, состав, рука

- **Гипотеза:** C14/8 лучше даёт увидеть ядро и новые карты без чрезмерно одинаковых начал; 16/8 может лучше беречь HP.
- **Параметры:** фиксированные C/L ядра 14, размеры 14/16/18 с одинаковыми явно названными добавками, руки 7/8; отдельно буквальный текущий 18. При изменении руки состав идентичен. Универсального «размера без изменения карт» физически нет: оценивается заданный способ разбавления.
- **Контроль:** текущий 18/8, экономика B, девять нынешних врагов; в следующем этапе — тот же новый сектор для всех вариантов.
- **Метрики:** ходы, обе потери HP, реальные mana spent/available включая победный ход, hand distribution, доступная защита/комбо, доля 5 маны, повторяемость начальных последовательностей; затем полные public-маршруты с одним драфтом.
- **Объём:** первичная проверка уже выполнена: 128 seed ×2 диапазона, по 16 на planner в каждом, 68 544 отдельных боя и 9 216 текущих походов. Для нового сектора ≥300+300 seed на классическую политику, ≥60+60 на planner; 12–20 человек по нескольку освоенных попыток.
- **Решение:** выбирать Pareto-компромисс темпа/безопасности/интересных решений; преимущество одной risky-эвристики не достаточно. Возврат к 16 допустим, если 14 слишком однообразна или увеличивает неуправляемые провалы. Не считать 1–3 п.п. доказанным без оценки неопределённости.
- **Ограничения:** full-HP бои не оценивают поход; общий состав+порядок допкарт влияет на «эффект размера»; scripted драфт не строит лучший человеческий архетип.

## E02 — экземпляры, операции и сейв

19.10.2026: foundation-подмножество выполнено — 1 000 фиксированных последовательностей операций/сейва, граничные проверки, текущий suite и browser smoke. [Отчёт](card-progression-foundation-v1-report.md). Реальные эффекты улучшений, золото и новые reward-треки ещё отсутствуют; эти части E02 проверяются при их реализации.

- **Гипотеза:** все операции однократны и воспроизводимы на конкретных копиях.
- **Параметры:** duplicate definitions, upgrade0/1, золото уникально, pending треки, reload/повтор команды, сбой записи, старая версия данных.
- **Контроль:** текущий движок и старые CardId-колоды через совместимый путь, исторические fixture без переписывания.
- **Метрики:** сохранность/уникальность ID, отсутствие дублей/потери карт, round-trip state, совпадение действий боя, отсутствие повторной награды; понятность старой/новой карты при выборе.
- **Объём:** детерминированные граничные кейсы и ≥1 000 generated последовательностей операций с фиксированными seed; browser smoke каждой сохранённой фазы, текущий полный suite. Это проверка инвариантов, не win-rate-тест.
- **Решение:** ни одной известной потери/повторного приза/невалидного load; ошибка сохранения явно видна, старый backup доступен. Сбой одного трека не откатывает уже завершённый другой.
- **Ограничения:** один выбранный storage/browser не доказывает все браузеры/Tauri; migration поддерживает объявленные версии, не произвольное будущее.

## E03 — кривая силы

- **Гипотеза:** одинаковый бюджет развития меняет тактические возможности и эффективность, а не только размер.
- **Параметры:** старт; +4/+8 обычных приобретений; те же с 2/4 улучшениями; замена/удаление; одна золотая; один предмет; их заранее объявленные комбинации. Отдельно готовые архетипы и реальные snapshots драфта после каждого сектора.
- **Контроль:** один seed/враг на всех стадиях, полное одинаковое HP для изолированного сравнения; отдельный перенос HP для походов. Карты/улучшения реализованы через канонический resolver.
- **Метрики:** ходы, W/M HP, spent/available и качество оставшейся руки; какие улучшенные/золотые увидены и сыграны; срабатывания Уязвимости/брони/Кровотечения, невозможность собрать комбинацию, лишняя броня, блокировки добора. Не сводить всё к одному «баллу силы».
- **Объём:** ≥300 main+300 holdout на врага/пакет для двух классических профилей; planner ≥60+60. Для драфтов ≥500 настоящих походов на политику, если движок/вычислительный бюджет позволяют; сначала smaller screening с явно меньшей уверенностью.
- **Решение:** у развитой атакующей сборки ожидается примерно ≥15% темпа без катастрофического роста потерь; у защитной — ≥20% уменьшения потерь при сопоставимом темпе. Это разные критерии, **не требование обоих улучшений одновременно каждой колоде**. Нужны новые осмысленные последовательности, а не одна золотая, лучшая в любом состоянии.
- **Ограничения:** нельзя сейчас симулировать отсутствующие улучшения подменой каталога и объявить их проверенными; этот опыт проводится после этапа 2. Собранная вручную идеальная колода не доказывает доступность через награды.

## E04 — четыре золотые и конечность эффектов

- **Гипотеза:** G01–04 полезны разным стратегиям, G04 вознаграждает оба класса без манового цикла.
- **Параметры:** каждая карта отдельно; пары с архетипом/предметом; порядок классов, убийство, исчерпанная колода, расход выбывания, сохранённые/улучшенные копии.
- **Контроль:** тот же бюджет полезных обычных/улучшенных карт, не обязательно слабая стартовая карта той же стоимости.
- **Метрики:** условная доля выбора, применение, изменение маршрута/темпа/HP, максимальные легальные розыгрыши, конечность ресурсной цепочки, исчерпание пула уникальных предложений.
- **Объём:** граничные tests всех эффектов, E03-sized screening на основных архетипах; 12–20 участников, несколько повторных предложений в разных состояниях.
- **Решение:** устойчивый выбор >85–90% во всех архетипах — сигнал пересмотра, не автоматический запрет; низкий выбор при отсутствии поддержки не доказывает слабость. Не должно быть пути повторять бесплатную генерацию ресурса или обходить уникальность.
- **Ограничения:** ранние четыре не отражают будущий каталог восемь; «одна копия» не ограничивает повтор после сброса без выбывания/мана-цены.

## E05 — R2 против трофейной модели элит

- **Гипотеза:** R2 даёт больше контекстных решений, модель Claude — более сильный эмоциональный приз, но потенциально больше снежного кома.
- **Параметры:** R2 (1 gold+2 upgraded / artifact1of2-or-upgrade) и Claude (gold1of3 +тематический artifact1of2). Одинаковые доступные каталоги/уникальность/2 слота. Затем отдельно вариант с нормализованной шириной карточного выбора, чтобы отделить роль «три золотые» от силы предмета.
- **Контроль:** тот же элитный бой/entry state. Два дизайна: парный фиксированный вход для цены приза и полная адаптивная карта для привлекательности маршрута. Результаты не смешивать.
- **Метрики:** ущерб/время самой элиты; counterfactual skip/обычный путь; дополнительная эффективность в следующих 1/3/всех оставшихся боях; выбор карты/обычной альтернативы, отказ/замена предмета; состояние выбирающих элиту и число оставшихся боёв; победы без элит/без конкретной золотой.
- **Объём:** ≥300+300 пар entry state на раннюю/позднюю элиту; ≥500 route seed на политику; человеческий within-subject опыт 12–20 участников с чередованием порядка вариантов. По редким поздним сочетаниям расширять, а не усреднять с ранними.
- **Решение:** должны существовать воспроизводимые состояния, где разумно выбрать и пропустить элиту; безопасный путь остаётся жизнеспособным. >80% выбора даже раненым либо <20% здоровым — диагностический сигнал. Требование одинакового win rate safe/risky отменено: политики имеют разную осторожность и способность оценивать развитие.
- **Ограничения:** наблюдаемый выбор элит коррелирует с HP/сильной колодой. Разницу побед нельзя целиком приписать награде. Без реализованных улучшений/золота опыт преждевременен.

## E06 — здоровье A/B/C

- **Гипотеза:** B (split10+4 каждому) даёт достаточное управление и цену ран без сильного reset модели C.
- **Параметры:** A 6 одному/+4 каждому; B 10 распределить/+4; C 10 распределить/ceil(50% недостающего). Та же альтернатива «улучшить», события/предметы зафиксированы; отдельно crossover с одной weak/medium/strong кривой развития.
- **Контроль:** модель A, тот же ростер/seed/драфт. Для чистого эффекта количества лечения фиксировать решения «когда лечиться»; для поведения отдельно разрешить адаптацию. В обоих случаях перераспределение ботом формально описать.
- **Метрики:** HP W/M перед каждым боссом, deaths по герою/месту, over-heal, доля лагерей на лечение вместо улучшения, аварийные руки, итоговая сила, длительность. Survival curve включает недошедших.
- **Объём:** screening 300 main на конфигурацию, подтверждение ≥500+500 seed на жизнеспособных двух/трёхсекторных сценариях и нескольких архетипах; повторные человеческие походы.
- **Решение:** выбрать минимальную достаточную помощь, при которой ошибки остаются значимыми, а развитые разные сборки не гибнут преимущественно от неуправляемой концентрации урона. Если B всегда оставляет обоих полными при большинстве лагерей, её бюджет слишком велик или враги/кривая силы слишком мягкие. Не требовать искусственно равного числа смертей героев.
- **Ограничения:** исходная модель Claude не содержит A/B в точном виде, а модель Codex не содержит карточных решений. Синтетическое истощение — только sensitivity, не доказательство B.

## E07 — накопление предметов

- **Гипотеза:** два слота достаточны, новые три направления улучшают разнообразие без усиления каждой оборонительной колоды.
- **Параметры:** текущие пять, A06–08 по одному и попарно, раннее/позднее получение; замена против удержания; Полиспаст/Шкив с усиленными защитами.
- **Контроль:** no-artifact и один текущий предмет при равном сроке владения.
- **Метрики:** actual HP saved, дополнительный урон/ранее наступивший lethal, частота/причина срабатывания, отказы и замены, размер упущенной альтернативы слота.
- **Объём:** ≥300 paired боёв на опасное сочетание, ≥300 run seed раннего/позднего владения; отдельно ручной review редких цепочек.
- **Решение:** не расширять слот для лечения слабого предложения. Устранять автопик/универсальный двигатель адресной настройкой, затем проверять каталог.
- **Ограничения:** подсчёт +2 брони не равен двум сохранённым HP; предмет «раз за бой» в длинном походе имеет другие повторения.

## E08 — 18 против 21 и время

- **Гипотеза:** 18 даёт достаточную дистанцию развития при 40–55 мин; 21 нужен только если заметная часть новых карт не успевает использоваться.
- **Параметры:** одна конфигурационная архитектура, +один гибкий ряд в каждом секторе; бюджет наград/здоровья сначала явно зафиксирован, затем отдельная настройка. Не сравнивать старый бедный 18 и новый богатый 21 как чистую длину.
- **Контроль:** рабочий полный 18; знакомство участников сбалансировано, порядок версий чередуется.
- **Метрики:** время только активной игры по боям/экранам/чтению, число значимых перестроек, частота применения поздних приобретений, утомление/добровольное прекращение, желание нового похода.
- **Объём:** 12–20 человек ×не менее двух освоенных успешных/достаточно продвинутых попыток каждой версии; увеличить при сильном разбросе навыка. Боты не измеряют минуты человека.
- **Решение:** оставить 18, если развитие видно и цель времени достигается; 21 оправдан содержательной пользой, не желанием приблизиться к числу комнат StS.
- **Ограничения:** выбор только успешных попыток скрывает тяжёлые длинные поражения — их время и утомление показывать отдельно.

## E09 — наградный пул/сборка

- **Гипотеза:** полезные стартовые определения стоит сохранить, а два дополнительных источника Кровотечения и специализированные выплаты нужны сильнее, чем жёсткая подстройка.
- **Параметры:** текущие 20, расширение специализированными, исключение шести стартовых отдельной веткой; мягкая гарантия класса/подстройка только отдельным этапом.
- **Контроль:** равномерные уникальные предложения 1/3, правильный seeded shuffle; тот же размер каталога в причинном сравнении либо явно отметить изменение размера.
- **Метрики:** получить/сыграть источник и payoff, число мёртвых выборов, одновременные предложения нужных компонентов, пропуски, финальные копии/силы; сила реально полученного пакета в боях.
- **Объём:** ≥10 000 cheap offer-моделей на каждую политику, затем ≥500 engine-походов на shortlist. Это разные классы доказательств.
- **Решение:** не считать критерий «две карты-наложения+две выплаты» доказательством работы сборки; защита/мана/порядок/remaining fights тоже нужны. Не гарантировать идеальный комплект.
- **Ограничения:** original synergy-odds использует корректный Fisher–Yates, но условная greedy-политика и критерий успеха не являются человеческим драфтом.

## E10 — генерация и качество маршрута

- **Гипотеза:** прорезанные пути с опорами и сервисами дают разные применимые планы при структурной корректности.
- **Параметры:** 18/21, число путей/ширина/допустимые типы, конфигурации секторов; независимые scope seed и fallback.
- **Контроль:** нынешняя карта как регрессия публичности, новая конфигурация не обязана повторять её контент/граф.
- **Метрики:** все инварианты §9, количество/доля профилей N/E/услуг, доступ лечения/развития, число отклонений и fallback, совпадение категорий/операций, выборы людей. Геометрические пути только справочная величина.
- **Объём:** сначала ≥1 000 regression seed, затем ≥10 000 на конфигурацию плюс seeds у границ uint32 и все зарегистрированные сбои. Полный анализ достижимости/профилей на каждой карте, а не одна случайная прогулка.
- **Решение:** ноль структурных нарушений; fallback редок/понятен и сам валиден, обе риск-политики имеют реальные возможности. Никакого универсального «экономического доминирования» из фиксированного веса комнаты.
- **Ограничения:** старый Codex topology на 21 не тестирует новый 18-carved генератор; этот опыт проводится после его реализации в этапе 3.

## E11 — вопросы врагов/боссов

- **Гипотеза:** варианты меняют порядок/распределение защиты; один новый механизм II достаточно разнообразит раннюю игру.
- **Параметры:** те же реальные руки против каждого врага/варианта, ослабление подготовки on/off, фазы, типы наводки. Никаких одновременных nine-hook пакетов.
- **Контроль:** базовые действия текущего движка и неизменяемая раскрытая цель; новый контент сравнён при сходном бюджете HP/темпа.
- **Метрики:** изменился ли разумный порядок карт, цена защиты обоих, выбор наступления вместо ослабления/блока, ясность прогресса, HP/turns, корректность public preview.
- **Объём:** ≥300 shuffled-deck seed на врага и профиль; набор hand fixtures для решений; ≥8–12 человек для первого экрана намерения, больше для сложности.
- **Решение:** если «вариант» вызывает тот же план почти всегда, переосмыслить/сократить, а не добавить арт. Для босса нужны жизнеспособные разные направления без конкретного золота.
- **Ограничения:** одинаковая последовательность у ограниченного бота не доказывает отсутствие глубины; ручной анализ причин обязателен.

## E12 — события/флаги

- **Гипотеза:** шесть событий выполняют разные функции с ограниченным влиянием и понятной отложенной ценой.
- **Параметры:** все ветки/пороги HP/занятые слоты/полный HP/пустой допустимый пул, флаги E04/E06, повтор команды/загрузки.
- **Контроль:** уход без наказания; одинаковый seed/исход после повторной загрузки.
- **Метрики:** ошибки транзакции, скрытая летальность, применение будущего эффекта, выборы в разных состояниях, эффект события относительно одного обычного боя/улучшения.
- **Объём:** детерминированное покрытие всех веток, ≥100 generated состояния на событие, 8–12 человек на читаемость до длительного похода.
- **Решение:** нет скрытой смертельной платы, двойного расхода/приза; последствия понимаются до выбора. Высокий общий pick rate не баг, если состояния объясняют его.
- **Ограничения:** ветки не обязаны выбираться по 50%; сильный отложенный флаг зависит от того, сколько похода осталось.
