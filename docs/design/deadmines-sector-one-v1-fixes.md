## Реализация

- **B1:** назначение обычных встреч учитывает всех предков узла. Детерминированный поиск с возвратом пересматривает предыдущие назначения при слиянии путей. Сначала ищется решение без соседних одинаковых семейств (сервисные комнаты не обрывают последовательность боёв); если оно невозможно, семейства становятся предпочтением, уникальность вариантов остаётся обязательной. Два поиска ограничены по 50 000 шагов, внешняя генерация — 128 попытками. Недостаточный пул завершается явной ошибкой, повтор вариантов не разрешается. Валидатор отдельно проверяет множества вариантов предков. Семейства заданы отдельными метаданными, боевые определения не менялись.
- **B2:** списки удаления/замены различают номер копии, ↑ и уровень. Выбранная копия показана существующим `SpellCard` через `resolveCardDefinition`, поэтому видны её реальные улучшенные эффекты. В постоянно видимом подтверждении указаны старая и новая карты и явная потеря улучшения. Журнал тоже сохраняет ↑ удалённой/заменённой копии.
- **B3:** FNV используется только для выделения seed потока; исход берётся первым значением существующего Mulberry32 (`nextRandom` из `deck.ts`). Локальный объект RNG не связан с боем. Reload не меняет предложения и исход.
- **B4:** контракт `roomRules` включает размеры предложений, цены HP, вероятность, алгоритм исхода, версии фильтра замен/допуска копий и поведение пустого пула. `roomRulesVersion` содержит явную версию и fingerprint всего контракта. Изменение чисел меняет fingerprint автоматически; изменение семантики требует поднять явную версию. UI, игровые операции и проверка размеров сохранения используют эти константы/общие функции.
- **B7:** замены — только `reward`, без `excludedRewards`, того же класса, без исходного определения, уровня 0. Все текущие карты имеют обычную редкость; золотая редкость ещё не вводилась. Создание новой копии идёт через прежнюю общую транзакцию приобретения. `roomReplacementOptions` един для UI и правил: из сохранённых кандидатов показывается максимум три. При дефиците предложения сокращаются, пустая замена отключается. Даже при исключении всех наград кузница открывается и позволяет удалять/улучшать; пустые награды недоступны.
- **B8:** ID теперь `deadmines-old-mines/layer-N-column-M` и `deadmines-old-mines/final`. Поэтому существующие battle/reward/room scopes, решения и журнал автоматически включают сектор. Тест двух конфигов с разными ID проверяет разделение идентификаторов и потоков. Исправлен разбор суффикса ID для существующих портретов. Переходов между секторами, `sectors[]` и контента II нет.
- **B10:** модальное подтверждение называет плательщика и переход HP, например «Платит Джайна Праудмур: 18 → 15 HP», включая кнопку.
- **B9/B14, частично:** убран вложенный скролл списка копий, закреплена сводка замены. Общими стали доступность действий, фильтрация/ограничение замен и параметры комнат. Полного изменения раскладки нет.

## Независимая проверка B1

`node scripts/check-sector-review.mjs 10000` сравнивает исходный генератор из Git с исправленным на **одинаковых seed 0…9999**. Старый исходник загружается только в память через Vite. Оракул `research/sector-review/oracle.ts` сам обходит рёбра DFS и не вызывает `sectorPaths` или `validateSectorMap`. Проверяет реальную достижимость, продолжение без обязательной элиты, бюджеты всех маршрутов, несовместимость боя ряда 2 с элитой ряда 3, пересечения, привал/босса и отсутствие повторов вариантов. Проверены также uint32-границы.

| Метрика | До | После |
|---|---:|---:|
| Карт | 10 000 | 10 000 |
| Реальных путей | 191 418 | 192 193 |
| Путей с повтором варианта | 34,679% | **0%** |
| Соседних одинаковых семейств / пар боёв | 15,361% | **0%** |
| Других нарушений / исчерпаний 128 попыток | 0 / 0 | **0 / 0** |
| Среднее число попыток | 7,8356 | 7,8533 |
| P99 / максимум попыток | 34 / 66 | 34 / 74 |
| Уникальных топологий | 9 980 | 9 984 |
| Наборов последовательностей категорий | 31 | 31 |
| Путей на карту / последовательностей на карту | 19,1418 / 4,0033 | 19,2193 / 4,0037 |
| Доля путей через элиту | 22,667% | 22,819% |
| Через кузницу / событие | 39,001% / 69,516% | 38,971% / 69,964% |

Таким образом B1 независимо воспроизведён: исходные 34,7% совпадают с ревью. Знаменатель метрики семейства здесь — пары боёв; процент из ревью относится к иной агрегации, напрямую их сравнивать нельзя.

Смена версии генератора и ID меняет новые карты того же seed: старый seed-layout не обещается сохранять между версиями. Распределение категорий практически сохранилось. Распределение вариантов ожидаемо изменилось: Налётчик / Забойщик / Дозорный / Надсмотрщик по узлам были 16 470 / 26 760 / 26 265 / 13 334, стали 15 093 / 17 941 / 24 472 / 25 153. Исключение повторов семейств чаще ставит Надсмотрщика позже; это изменение состава встреч, а не их боевых параметров. Старые маршрутные балансовые результаты остаются историческими и не выдаются за измерение новой раскладки.

| Старые ID / Mulberry32 | 70,18% | 69,85% | 58,77% | 58,01% |

## Сохранения и проверки

Генератор: `carved-paths-2`. Новые секторные снимки схемы 2 обязательно содержат `roomRulesVersion`. Предыдущая экспериментальная реализация Sector I (`carved-paths-1`, без версии комнат) **намеренно несовместима**: изменились ID, фильтры и исходы. Она распознаётся как `IncompatibleSave`, до повторного вычисления комнаты. Основная запись и backup остаются нетронутыми и доступны для экспорта; автоматического отката к старшему совместимому backup нет. Автоматической миграции/регенерации старого сектора нет.

Обычная старая кампания и ранее поддержанные foundation/upgrades-снимки схемы 1 читаются прежним путём; новый секторный контракт от них не требуется. Их сохранение текущей игрой по-прежнему записывает схему 2: откат приложения на старый `main` может потребовать прежний экспорт/прежнюю сборку (B18).

- `npm test`: **27 файлов, 644 теста**, все прошли; добавлены 13 тестов ревью. Исторический эталон **427 боёв** прошёл без обновления.
- `npm run build`: успешно. Остаётся прежнее предупреждение Vite о чанке >500 KB (теперь около 577 KB).
- `npm run scenarios -- 42`: контрольные сценарии выполнены, предусмотренные победа/поражение/отказ по мане сохранены; тесты сценариев прошли.
- Новые проверки: независимые маршруты 1 000 seed в Vitest; конкретные мутации повторов/боевого бюджета/обязательной элиты/пересечения/достижимости; ограниченное завершение при недостаточном пуле; раздельные scopes двух секторов; сохранность 32/36/34/40/60/65 HP и 18/8/3; оплата **4→1 HP**, отказ при 3; риск при **3 HP**, отказ при 2 у любого героя, провал снимает по 2 обоим; размеры 3/2/3; отказ скрытому четвёртому кандидату и другому классу; исключения и пустой пул; уникальность журнала и повторные команды; reload черновика/исхода/применённой операции; несовместимый контракт с корректной checksum и сохранностью обоих исходников; SSR реального компонента для ↑, предупреждений и оплаты HP.
- Полный мутационный прогон Claude (20 мутантов) заново не запускался; отчёт не утверждает, что убиты все его мутанты.
