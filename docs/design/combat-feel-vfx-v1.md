# Combat Feel & VFX v1

Ветка `feature/combat-feel-vfx-v1`, база — `main` на `d0380ab`. Это отчёт этапа боевой визуализации: правила, баланс, экономика и сохранения не менялись.

Итог одной строкой: эффекты теперь выбираются **по тому, что движок реально решил** (урон, броня, статусы, добор — из `PendingPlay` и прогноза врага), а не по `card.kind`; рисуются одним небольшим PixiJS-рантаймом; показывают только происходящее; укладываются в 0,5–1 с и помогают читать бой.

## 1. Что было до изменений

`BattleFx.vue` (410 строк) содержал и расчёт сцены, и все эффекты. Вид выбирался по `card.kind` (и по грубому `effect` врага):

| Ситуация | Что рисовалось |
| --- | --- |
| любая «атака» Воина | один золотой росчерк меча |
| любое заклинание, включая добор | один огненный шар с фиолетовым ореолом |
| любая защита | один голубой щит |
| удар по героям | тот же росчерк; для двух героев — два росчерка |
| подготовка, срыв | кольцо «АТАКА ГОТОВИТСЯ»; сорванный удар играл то же кольцо |

Проблемы: Ледяная стрела и Грозовой разряд летели огненным шаром; Тайное предвидение «атаковало» врага и трясло его портрет; все числа появлялись в центре портрета одним форматом; поглощение бронёй, полный блок, бронебой и разрушение брони не различались; ни одно событие статуса (Уязвимость, Кровотечение, Обморожение) не имело своего отклика; у каждого эффекта был свой `ticker`-колбэк (одна вспышка — до 16 колбэков); не учитывался `prefers-reduced-motion`. Тайминги были зашиты (`560/880`, `820/1300`, `1120`).

## 2. Как теперь определяется эффект

```
движок                                    src/vfx                                  экран
──────                                    ───────                                  ─────
startCardPlay → PendingPlay ──┐
  effects, consumedStatuses,  ├─► cardVfxPlan(card, play, state) ─┐
  preview (урон по броне/HP,  │                                   │
  броня героев, добор, статусы)                                   ├─► VfxPlan ─► BattleFx ─► FxRuntime ─► painters
forecastEnemyAction ──────────┴─► enemyVfxPlan(state, forecast) ──┘     (биты)    runPlan    1 ticker
  (для подготовки — publicIntent)                                                    │
                                                                                     └─► impact(actionId) ─► resolvePlay / finishTurn
```

`VfxPlan` — упорядоченный список **битов** со временем от начала (`at`, `durMs`) и ровно одним моментом удара `impactMs`. Бит — это одно «событие на экране»: `strike`, `guard`, `rune`, `status`, `draw`, `gather`, `break`, `result`, `armor-fx`, `number`. План — чистые данные: его можно проверить тестом, показать в лаборатории и воспроизвести.

Ключевые правила построения (`src/vfx/plan.ts`):

* **Бит существует только потому, что движок сказал, что это случилось.** Расход Уязвимости — это `consumedStatuses`; раскол льда — `consumedStatuses` с `frostbite` (при отсутствии Обморожения его просто нет в плане); тик Кровотечения — `preview.statusDamage > 0`; усиление синергией — `armorBonus`/`artifactDamage > 0`; разрушение брони врага — `enemy.armor − preview.armorDamage ≤ 0`; наложение статуса — достижимый эффект `status` (повторное наложение статуса, который не складывается и уже есть, не показывается).
* **Вид карты берётся по ID** из таблицы `cardStyles.ts` (школа: физика, огонь, лёд, молния, аркана, кровь; тип удара; тип брони). Таблица — `Record<CardId, …>`: компилятор потребует запись для новой карты, а неизвестная карта получает осмысленный вид по классу и форме. Что карта *делает*, из таблицы не читается никогда.
* **Тяжесть** удара — по числу, которое видит игрок (≤3 лёгкий, ≥9 тяжёлый); обычный взмах, ставший тяжёлым из-за бонусов, рисуется как рубящий удар.
* **Числа** берутся из прогноза/превью, с приоритетом: здоровье → поглощение бронёй → тик статуса → полученная броня → бонусы → статусы. На один портрет приходится не больше четырёх надписей одновременно (дорожки без наложения, лишние отбрасываются по приоритету).
* **Скрытое остаётся скрытым.** План подготовленной атаки строится только из `publicIntent` (цель и «что-то готовится»): размер, бронебой и срыв в нём отсутствуют, и два плана для удара 3 и удара 40 совпадают побитно (тест).

## 3. Что создано и переработано

Архитектура (`src/vfx/`, 11 файлов + 4 painter-файла):

| Модуль | Задача |
| --- | --- |
| `types.ts` | словарь: школы, веса, биты, `VfxPlan`, `Reaction` |
| `cardStyles.ts` | школа и вид каждой карты по ID |
| `plan.ts` | `cardVfxPlan`, `enemyVfxPlan`, расстановка дорожек чисел, режим reduced motion |
| `timing.ts` | единые тайминги: момент попадания и хвост каждого типа удара |
| `run.ts` | `runPlan`: удар сообщается один раз; каждый бит проверяет `current()` |
| `timeline.ts`, `particles.ts` | детерминированные часы; пул частиц с жёстким лимитом (200, при reduced — 24) |
| `motion.ts` | `prefers-reduced-motion` + переопределение для будущих настроек |
| `runtime.ts` | PixiJS: **один** ticker-колбэк, три перерисовываемых `Graphics` (под/свет/над), пул `Text`, якоря `data-fx-anchor` |
| `painters/` | рисование: удары, защита, статусы, руны, подготовка |
| `scenarios.ts` | воспроизводимые сцены лаборатории (53 штуки) |

`BattleFx.vue` сократился до тонкой оболочки (запуск плана, `impact`, очистка). Кадры героев и врага получили вес реакции (`hit-weight`: лёгкая/обычная/тяжёлая отдача) вместо одной общей тряски.

### Эффекты

**Вариан (физика).** Росчерк клинка — полумесяц, утолщающийся к середине, золотой с белым ядром; шипастая вспышка попадания, металлические искры. *Быстрый выпад* — узкий прямой укол за 90 мс. *Тяжёлый удар* — занос и широкая рубящая дуга, двойное кольцо, трещины, осколки металла. *Удар щитом* — щит летит от Вариана к врагу со шлейфом и бьёт «металлическим импульсом» (кольцо, лучи, искры).

**Кровь.** Алые три царапины и капли при наложении; красный импульс-кольцо при тике (и перед атакой врага); большой алый всплеск с каплями при расходе в «Кровавой расплате».

**Джайна (школы).** *Огненный шар* — оранжево-золотой снаряд с углями и фиолетовым ореолом, вспышка огня. *Ледяная стрела* — кристалл с морозным шлейфом, осколки при попадании. *Грозовой разряд* — мгновенная ломаная молния с ветвями и мерцанием (быстрее шара: удар на 140 мс против 380). *Арканные руны* — вращающийся круг с символом (над целью для «метки», вокруг героини для «предвидения»); карта без урона не показывает снаряда, добор — потоком искр в руку. *Ледяная хватка* — порыв холода и ледяная решётка вокруг портрета. *Кровавый резонанс* — арканный снаряд в алых тонах.

**Статусы.** Уязвимость наложена — золотая прицельная метка сходится на цели; израсходована — метка рассыпается четырьмя дугами и лучами. Обморожение наложено — ледяная решётка; израсходовано — трещины и разлёт осколков. Ярость врага — огненная вспышка. Срыв атаки — кольцо распадается на дуги без попадания по героям.

**Защита.** Воин — стальной щит-«капля» с бронзовым ободом и золотым умбоном, вспышка «клац». Маг — полупрозрачный шестиугольный барьер с рунами (аркана — фиолетовый, лёд — голубой с кристаллами). Каждый герой получает свой щит отдельно. Броня врага — железные пластины вокруг медальона.

**Атаки врагов.** Обычная — рывок и три когтевых росчерка по герою; тяжёлая — комета-таран, ударная волна, обломки, пыль и трещины; групповая — два попадания с интервалом 110 мс (результат применяется один раз); бронебой — тонкая игла, проходящая сквозь кольцо с разрывом; подготовка — сходящиеся искры и ободок на целях. Рак’Зор: магмовая палитра, более крупные волны и кольца, тяжёлая форма для групповых ударов, поднимающиеся угли.

**Итоги удара по герою** различаются и по числам, и по картинке: *полный блок* (стальной/магический щит вспыхивает и гаснет, «БЛОК», «−N брони», без потери здоровья и без дрожи портрета), *частичное поглощение* (щит раскалывается, «−N брони» и «−M»), *прямой удар*, *бронебой*, *ослабленный до нуля* («Ослаблено», без вспышки). Ни одна надпись не показывает `−0`.

**Числа.** Сцена измеряет якоря и ставит числа выше середины медальона врага и в нижней половине арки героя (имя, здоровье и намерение остаются свободными). Размер — от `xl` (тяжёлый удар) до `s` (статус); тяжёлое число «падает» с увеличенного размера. Дрожь — только локальная и короткая, по весу удара; тряски экрана нет.

## 4. Карты с индивидуальными сценариями

Все 25 карт каталога (23 + 2 экспериментальные карты B2) имеют запись в `cardStyles.ts`; индивидуальные внешние сценарии:

`sword-strike` (взмах), `quick-cut` (укол), `crushing-swing` (рубящий), `shield-bash` (удар щитом), `rend` (взмах + Кровотечение), `reaping-blow` (рубящий + всплеск крови), `stance-strike` (взмах + щит напарнику + акцент синергии), `ice-breaker` (взмах + раскол льда только при Обморожении), `guard`, `bastion`, `interpose`, `wound-clamp` (стальной щит; у `wound-clamp` ещё тик), `parry`, `covering-counter` (щит + контрудар только против атакующего врага), `fireball`, `frostbolt`, `thunderbolt`, `frost-grip`, `ice-echo`, `ice-ward` (ледяной барьер обоим), `arcane-insight`, `arcane-mark`, `boil-blood`, `frost-seal` (руны без снаряда), `blood-resonance`.

## 5. Синхронизация PixiJS и движка

Сохранены все гарантии прежней схемы:

* **Корреляция по `actionId`.** `useBattleAnimation` по-прежнему выдаёт `animation/N`; `BattleFx` сообщает `impact(actionId)`, composable принимает только текущий ID.
* **Однократное применение.** `runPlan` ставит ровно один `onImpact` (флаг `reported`); повторные события от Pixi, резервного таймера и таймера восстановления гасятся прежней логикой `pending`. Новые «декоративные» биты (числа, статусы, второй щит, добор) стоят после удара по времени и состояния игры не трогают.
* **Резервный таймер.** `fallbackImpactMs = impactMs + 260`, `recoveryMs ≥ конец последнего бита`. Если холст ничего не сообщил (скрытая вкладка, нет WebGL), действие применится по таймеру, ввод освободится вовремя.
* **Отмена и устаревшие действия.** Каждый запланированный бит и сам удар проверяют `current()` (тот же `actionId`, тот же рантайм, не размонтировано). Новый план вызывает `runtime.begin → clear`: часы, актёры, частицы, надписи сбрасываются; при возврате на вкладку после скрытия старые эффекты тоже сбрасываются.
* **Групповая атака.** Два визуальных попадания, один `impact` — после последнего (тест на реальном движке: `finishTurn` вызывается один раз, оба героя теряют здоровье один раз).
* **Реакция портретов** выводится из плана: двигается только тот, кто *правда* теряет здоровье (или получает тик). Полный блок, добор и статус портрет не трогают (раньше «Тайное предвидение» трясло врага).
* Тайминги игрового состояния не менялись; изменились только `recoveryMs` и `fallbackImpactMs` (теперь из плана: быстрее для лёгких ударов, чуть длиннее для тяжёлых).

## 6. Reduced motion

`currentMotion()` читает `prefers-reduced-motion: reduce` (с возможностью переопределить через `setMotionPreference` — будущая настройка, меню пока нет). План строится заново в режиме `reduced`: те же биты и те же числа, но попадание на ~40 % времени, без полёта частиц (пул 24, остаются только круглые точки), удары — одна спокойная вспышка и кольцо в точке контакта, числа не плывут вверх, а только появляются и гаснут, щиты и руны — плавное появление. CSS-тряска портретов гасится существующим правилом `prefers-reduced-motion` в `main.css`. Лаборатория: `&motion=reduced` или переключатель.

## 7. Тесты

Новые файлы: `src/vfx/plan.test.ts` (33 теста), `src/vfx/run.test.ts` (9), `src/composables/useBattleAnimation.vfx.test.ts` (8). Существующие тесты `useBattleAnimation.test.ts` не менялись и проходят; в трёх UI-тестах, которые собирают объект анимации вручную, добавлены новые поля `vfx` и `reaction`.

Проверяется:
* огненный шар и ледяная стрела получают разные эффекты и школы; `arcane-insight` (и `arcane-mark`, `boil-blood`, `frost-seal`) не создают ни одного `strike`; `thunderbolt` — молния и быстрее шара;
* защитные карты разных классов различаются, каждый герой получает свой щит с числом из превью;
* `ice-breaker` показывает раскол **только** при реально потраченном Обморожении; расход/наложение Уязвимости, Кровотечения (наложение, всплеск, тик) — только когда это происходит;
* удар по броне врага: «держит» или «разбита» ровно по расчёту движка; полностью поглощённый удар не даёт числа здоровья и реакции;
* на каждой из 53 сцен лаборатории числа плана **равны** реальным потерям (здоровье врага после `resolveCardPlay`, здоровье героев после `endTurn`, тик Кровотечения); нигде нет `−0`;
* групповая атака применяется один раз; отменённое и устаревшее действие не рисуют и не бьют; быстрый второй розыгрыш не оставляет битов первого; резервный таймер применяет действие, если холст молчит, и освобождает ввод вовремя;
* reduced motion сохраняет события и числа, ускоряет, не ломает применение;
* подготовленный удар неотличим при разных скрытых числах, броне и свойствах;
* все биты укладываются в `endMs ≤ recoveryMs`; не больше четырёх надписей на портрет;
* пул частиц держит лимит и переиспользует объекты; часы и раннер ведут себя детерминированно.

## 9. Что осталось общим и почему

* **Рамки портретов** (`HeroFrame`/`EnemyFrame`) по-прежнему реагируют CSS-анимацией, а не Pixi: так отдача привязана к реальному DOM-слою и не дублируется на холсте; добавлены только три веса.
* **Один общий «стальной щит»** для всех карт Воина и один «барьер» для магии (аркана/лёд различаются цветом и кристаллами): отдельный щит на каждую карту не окупился бы по читаемости.
* **Групповой удар обычного врага** использует тот же коготь/таран, что и одиночный: различается число попаданий и порядок, а не форма.
* **Враги без отдельного сценария.** Эффекты врага зависят от типа удара, не от конкретного врага; Рак’Зор получает отдельный вариант через общий флаг `boss`. Смена фазы Рак’Зора не анимировалась (вне этапа).
* **Звук, фоны, дым** — вне этапа.

## 10. Что улучшить дальше

* Индивидуальные сценарии отдельных врагов (удар киркой, болт арбалетчика, молот бригадира) и специальная вспышка начала второй фазы Рак’Зора.
* Спрайтовые текстуры (мазки, дым, искры) вместо векторных форм там, где нужна «живописность» стиля.
* Подсветка Уязвимости на портрете героя после метки; «ломающиеся» цифры при смертельном ударе.
* Пользовательская настройка эффектов (полный/спокойный/выкл.): API `setMotionPreference` уже есть.
* Звуковая привязка к битам: `VfxPlan` уже содержит моменты `impactMs` и биты по типам.
* Оживление шахтных фонов отдельным слоем.
