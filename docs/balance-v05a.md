# Spellwhim — Balance Lab v0.5a

## Назначение

Headless-инструмент запускает настоящие бои в последовательности похода, выбирает награды и сохраняет статистику для проверки баланса. Он использует `createBattle`, `playCard`, `endTurn`, `forecastEnemyAction` и общие операции кампании. Отдельной упрощённой модели боя нет. Интерфейс, PixiJS и Tauri для расчёта не нужны.

Браузерная игра и симулятор разделяют создание боя, порядок встреч, перенос здоровья, сброс брони между встречами, список наград и правило перехода после победы. Операции находятся в `src/game/campaign.ts`; состояние боя остаётся источником истины в `src/game/battle.ts`.

## Стратегии

- **Aggressive** максимизирует ожидаемый урон и темп, отбрасывает защитные карты, кроме случаев гарантированной смертельной угрозы. Награду выбирает с уклоном в атаку.
- **Defensive** ценит броню, которая поглощает объявленную атаку, затем атакует. Награда зависит от текущего здоровья и состояния колоды.
- **Balanced** оценивает текущий входящий урон, атаку, добор и доступные связки. Пересчитывает оценки после каждой карты, поэтому может подготовить и использовать связку в одном ходу.

Каждая стратегия видит только текущую руку, объявленное намерение врага, состояние героев и колоду. Порядок будущих карт не раскрывается. Алгоритмы детерминированы; это базовые эвристики, не модель опытного игрока.

## Запуск

```bash
npm run balance -- --runs 200 --seed 42
npm run balance -- --runs 200 --seed 42 --strategy balanced
npm run balance -- --run 90 --strategy aggressive
npm run balance -- --runs 200 --seed 42 --json docs/balance-v05a-results.json
npm run balance:smoke
```

`--run` печатает подробную запись одного прохождения с журналом карт и действий противника по боям. Серия записывает seed, стратегию, исход, ход, здоровье, награды, карты, связки и действия в JSON при заданном `--json`. Для каждой стратегии используется один и тот же диапазон seed. Настройки лимитов боя и действий доступны через API симулятора; достижение лимита записывается как `timeout`, отдельно от поражения.

## Что показывают результаты

**Наблюдения:** защитные и сбалансированные эвристики выиграли все 200 походов каждая. Aggressive проходил первые две встречи во всех забегах, но проиграл пять раз боссу. Balanced закончил поход в среднем на 0,1 хода медленнее Defensive и имел на 1,1 HP меньше у Лиры; выборка не показывает значимого превосходства одного из них по темпу или здоровью. Защита заметно снижает измеренный урон, но в этой выборке не улучшила процент побед относительно Balanced.

**Гипотеза:** урон босса по обоим героям и короткие приоритеты Aggressive приводят к смертям, если партия затягивается; Defensive безопаснее, но тратит больше ходов на защитные карты. Проверить эту гипотезу можно сравнением подробных журналов поражений и альтернативными эвристиками, не меняя игровой баланс.

Условия, где Aggressive явно доминирует, не обнаружены: стратегия быстрее, но проигрывала чаще и оставляла меньше здоровья. На доступных данных риск третьей встречи важнее скорости.

## Ограничения и следующие шаги

- Это 200 seed и три hand-coded эвристики. Выборка и стратегии не представляют человеческую игру.
- Бот выбирает одну карту жадно и пересчитывает оценку после её розыгрыша; он не ищет все возможные комбинации хода и не строит дальний план.
- Выбор награды также эвристический. Низкое число розыгрышей может быть следствием как карты, так и выбора стратегии.
- Наблюдаемые проценты побед следует перепроверять на новых диапазонах seed и после изменений AI. Не балансировать карты только по малым различиям в этой выборке.
- Следующий полезный шаг анализа — сравнить журналы пяти поражений с альтернативными планами на ход, затем прогнать несколько непересекающихся диапазонов seed. Игровые стоимости, урон, здоровье и правила связок в v0.5a не менялись.
