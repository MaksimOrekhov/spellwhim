# Balance Lab — стратегия `planner`

Эта работа **не меняет игру**: правила боя, карты, мана, враги, награды и интерфейс остались прежними. Добавлен только инструмент оценки — бот, который планирует последовательность карт на весь ход. Три прежние стратегии (`aggressive`, `defensive`, `balanced`) не тронуты и дают прежние числа до сотых (195/200, 200/200, 200/200; 10,39 / 13,63 / 11,86 хода — см. `docs/combat-depth-v06.md`).

Планировщик создан по результатам исследования `research/mana/` (см. [исследование маны](mana-progression-research.md)), где было замечено, что жадный бот разыгрывает **0,19** связки за ход, а перебор последовательностей — около **0,75–0,79**. Из исследования перенесено только то, что нужно для оценки комбинаций; исследовательские правила (кривые маны, пересчёт врагов, «эхо связки» и т. д.) сюда **не вошли**.

> **Две реализации.** В `research/mana/core.ts` остаётся историческая версия планировщика: она нужна, чтобы воспроизводить таблицы исследования, и намеренно отличается (знает следующее объявленное действие врага, поддерживает экспериментальные кривые маны, скидки, «кульминацию»). Актуальный инструмент Balance Lab — `src/game/balancePlanner.ts`; исследовательская версия с ним не конкурирует и не должна использоваться как оценка стратегий.

## Архитектура

| Файл | Что делает |
|---|---|
| `src/game/balancePlanner.ts` | Новый модуль: `planTurn(state, options)`, `createTurnPlanner(options)`, `cloneBattleState`, `determinize`. Ни от Vue, ни от UI не зависит. |
| `src/game/balance.ts` | Добавлена стратегия `planner` (`BalanceStrategy = ClassicStrategy \| 'planner'`), списки `classicStrategies` и `allStrategies`, метрики маны, связок, продолжительности боёв и стоимости планирования. |
| `scripts/run-balance.mjs` | `--strategy planner`, `baseline`, `all` (теперь четыре), списки через запятую; новые таблицы; время по стратегиям. |
| `src/game/balancePlanner.test.ts` | 20 тестов планировщика. |

Решения:
- **Отдельный модуль.** `balance.ts` уже около 300 строк, оценка одной карты и план хода — разные задачи. Модуль можно тестировать отдельно и позже заменить профиль весов.
- **`simulateBalance` по умолчанию возвращает три классические стратегии** (как раньше), чтобы существующие отчёты и тесты не менялись; планировщик включается явно: `strategies: [...allStrategies]`. Команда `npm run balance` по умолчанию, наоборот, показывает **все четыре** — сравнение и есть её цель; `--strategy baseline` возвращает прежний набор из трёх.
- **Награды.** Выбор награды у `planner` использует таблицу `balanced`, чтобы сравнение стратегий не смешивалось с разными колодами по другим причинам.
- **Стоимость планирования измеряется в узлах поиска** (детерминированно, входит в запись прохода), а время в мс — только на уровне CLI.

## Как работает планировщик

1. Копирует живое состояние боя (`cloneBattleState`) и заменяет скрытый порядок колоды случайным порядком (`determinize`).
2. Поиском пучком (ширина 30, не более 900 узлов, глубина до 12 розыгрышей) перебирает последовательности карт. Каждый шаг — настоящий `playCard` на копии; одинаковые копии карт не перебираются дважды, повторы состояний отсекаются таблицей.
3. Каждый узел оценивается на состоянии **после настоящего `endTurn`**, то есть после видимого действия врага: урон по врагу и его броне, потеря здоровья героев (маг ×1,3), штраф за героя при смерти, остаточная броня на герое, который не получил удар, число карт, оставленных в руке, потерянные доборы. Победа — максимальный балл, поражение — минимальный.
4. `createTurnPlanner().next(state)` отдаёт карты плана по одной и **перепланирует**, если рука изменилась неожиданно (эффект добора открыл новые карты) или начался новый ход.

Правила не дублируются: используются `playCard`, `endTurn` и `drawCards` из движка. Единственная собственная часть, связанная с состоянием, — его копирование; тест сравнивает её со `structuredClone` и проверяет, что ни одна изменяемая зона не разделена по ссылке (новое поле `BattleState`, которое забыли скопировать, уронит тест).

## Какую информацию планировщик может использовать

Только то, что известно игроку в момент решения:

| Источник | Использует? |
|---|---|
| Рука, мана, статусы, сброс, выбывшие карты, здоровье и броня героев и врага | да |
| Объявленное действие врага (в том числе `prepare` с подготовленным ударом) | да, через настоящий `endTurn` |
| **Состав** колоды добора (колода минус всё увиденное) | да — игрок может вывести его сам |
| **Порядок** колоды добора и порядок перетасовки сброса | **нет** |
| `rngState`, `seed`, `battleId` и технические идентификаторы экземпляров карт | **нет** |
| Следующие действия врага после объявленного (скрипт `enemy.behavior`) | **нет** |

Как это обеспечено:
- Копия перед поиском **канонизируется**: колода и сброс сортируются по *определению карты* (идентификатор экземпляра используется только как нейтральный тай-брейк между одинаковыми копиями) и перетасовываются генератором планировщика. Его начальное значение вычисляется **только из наблюдаемой ситуации** (`observableSeed`: ход, мана, состав каждой зоны, здоровье и броня героев и врага, статусы, объявленное действие врага) плюс необязательная `salt` (по умолчанию 0). Balance Lab ничего не передаёт: ни `seed` похода, ни `rngState`, ни порядок колоды, ни ID карт на решение повлиять не могут.
- Оценка не читает прогноз следующего хода. В исследовательской версии такое слагаемое было («угроза следующего объявленного действия»); оно отброшено, потому что игрок в момент хода его не видит. Это сознательно консервативно: см. «Ограничения».
- Если во время плана срабатывает добор, настоящая карта открывается только после настоящего розыгрыша, и бот перепланирует с реальной рукой.

## Проверки корректности

В `balancePlanner.test.ts`:
- **Нет утечки скрытого порядка и технических деталей.** «Эквивалентный вид» состояния (обратный порядок колоды и сброса, другие `seed`, `rngState` и `battleId`, все экземпляры карт переименованы) даёт тот же план и ту же рабочую копию (6 seed); `observableSeed` одинаков для эквивалентных видов и меняется при настоящем изменении ситуации.
- **То же для интегрированной стратегии.** Тест записывает каждое решение, которое `simulateRun(seed, 'planner')` запрашивает у планировщика (6 походов), строит эквивалентный вид того же состояния и проверяет, что свежий планировщик выбирает ту же карту; кроме того, Balance Lab не передаёт планировщику никаких параметров.
- **Проверено «мутациями»:** возврат реального порядка колоды, добавление `state.seed` в генератор и сортировка по ID экземпляра — каждая из них роняет эти тесты.
- **Скрипт врага не читается.** Подмена будущих действий врага на смертельные не меняет план.
- **Не меняет живой бой.** Состояние до и после `planTurn` равно.
- **Воспроизводимость.** Один вход и одна `salt` дают один план; один seed даёт тот же проход.
- **Выбор комбинаций.** Из руки «меч, ледяная стрела, стойка» план — `стойка → ледяная стрела → меч` (обе связки срабатывают, в таком порядке); из «меч, шар» — `шар → меч` (17 урона). На 40 стартовых руках урон плана **равен максимуму полного перебора** настоящего движка (с ограничениями по умолчанию и без ограничений); перебор идёт в той же рабочей копии, которую видит планировщик.
- **Допустимость.** На 25 полных боях (разные враги, колода с наградами) каждая предложенная карта лежит в руке, её хватает по мане, нет `pending`, `playCard` возвращает `ok`, мана не отрицательна, рука ≤ 10, ни одна карта не теряется и не дублируется.
- **Ограничения поиска.** Рука из 10 карт при 10 мане: лимит узлов и глубины соблюдается; план всё равно возвращается.
- **Перепланирование после добора.**
- **Интеграция.** Три классические стратегии сохраняют точные числа отчёта v0.6; `planner` детерминирован, доходит до конца похода, считает узлы; на 40 seed он делает связок за ход больше, чем в 2,5 раза против `balanced`, и тратит более 90% маны.

Всего в проекте 89 тестов (до планировщика было 69), все проходят.

Одинаковые seed для всех стратегий, `npm run balance -- --runs 200 --seed 42`. Независимая проверка — 500 походов на seed 5000–5499: числа близки (в пределах ±0,3 хода, ±0,02 связки за ход и ±1 HP).

| Стратегия | Победы | Ходов за поход | Ходов по боям 1 / 2 / 3 | Здоровье Бранн / Лира в конце | Потеря HP за ход |
|---|---:|---:|---|---|---:|
| aggressive | 195/200 (97,5%) | 10,4 | 2,5 / 3,1 / 4,8 | 10,4 / 4,8 | 2,7 |
| defensive | 200/200 | 13,6 | 2,8 / 3,9 / 6,9 | 22,9 / 16,6 | 0,25 |
| balanced | 200/200 | 11,9 | 2,8 / 3,3 / 5,8 | 20,6 / 14,2 | 0,69 |

### Что показывают результаты

- **Комбинации.** Планировщик играет в **3,9 раза** больше связок за ход, чем `balanced`, в 3,4 раза больше, чем `aggressive`, и в 1,9 раза больше, чем `defensive`. Это главная находка: жадные боты почти не выстраивают цепочки, и прежний Balance Lab недооценивал потенциал пары героев.
- **Скорость.** Бои короче на 23% (9,2 хода против 11,9): 2,1 / 2,7 / 4,3 хода. Он не лучше всех по здоровью, зато быстрее всех.
- **Мана.** Использование маны (94%) почти равно `defensive`/`balanced` — выигрыш не в том, *сколько* маны тратится, а в том, *что* она покупает: на ту же ману приходится в среднем на 7% больше карт (2,23 против 2,09 за ход) и в 3–4 раза больше связок.
- **Здоровье.** Планировщик теряет больше здоровья за ход (1,11 против 0,69 у `balanced`), потому что выбирает темп; но к концу похода у него остаётся 32,9 HP из 43 против 34,8 у `balanced`. Самый осторожный стиль — `defensive` (39,5 из 43), ценой 13,6 хода.
- **Победы** не различают стратегии: при нынешнем балансе три из четырёх выигрывают 100%. Сравнивать нужно по скорости, ресурсам и связкам.

Двухманные карты (особенно «Удар щитом» и «Огненный шар») занимают две трети хода и не помещаются в цепочку. Простая броня («Ледяной покров») без связки ему не нужна.

## Ограничения алгоритма

1. **Горизонт — один ход.** Планировщик не копит ману и карты на будущее и не готовит двухходовые цепочки. Поэтому он недооценивает любые механики «накопления» (копилка маны, ожидание дорогой карты).
2. **Одна случайная раскладка колоды на ход.** Решения со случайными добор-эффектами принимаются по одному возможному будущему (а не по среднему по многим); при частом добор-эффекте это шумит.
3. **Консервативность по информации.** Отброшено слагаемое «угроза следующего действия врага». Игрок, знающий паттерн наизусть, мог бы его учитывать; планировщик — нет. Исследовательская версия с этим слагаемым давала примерно 0,79 связки за ход и чуть больше здоровья (на другой выборке seed), поэтому реальный потолок «опытного игрока» выше, чем у этого бота.
4. **Веса оценки — эвристика** (HP-эквиваленты, штраф за низкое здоровье, ценность оставшейся руки). Профиль один (`defaultPlannerProfile`), нет настройки «осторожный/агрессивный» — исследовательские профили в Balance Lab не перенесены.
5. **Пучок и лимит узлов** могут отсечь оптимум. На проверенных руках это не происходило (результат равен полному перебору), но гарантии нет; счётчик `planningTruncatedPlans` показывает, если лимит сработал.
6. **Награды выбираются по таблице `balanced`**, а не самим планировщиком.
7. **Это не модель человека.** Бот не ошибается, не устаёт и не читает интерфейс; победы ботов нельзя читать как «лёгкая/трудная игра».
8. Планировщик рассчитан на нынешний `BattleState` (два героя, один враг); новые зоны, цели или состояния потребуют обновить копирование (тест напомнит) и оценку.

## Запуск

```bash
npm run balance                                    # все четыре стратегии, 200 походов, seed 42
npm run balance -- --strategy planner --runs 500 --seed 5000
npm run balance -- --strategy baseline             # только три классические
npm run balance -- --strategy balanced,planner --json balance-reports/compare.json
npm run balance -- --run 90 --strategy planner     # подробный журнал одного прохода
npm run balance:smoke                              # 5 походов, все стратегии
```

## Исправление после ревью: генератор планировщика

Первая версия брала начальное значение генератора из `seed` похода (`entropy`) и сортировала колоду по ID экземпляров. Это не использовало порядок колоды, но формально ставило решение в зависимость от скрытых значений. Теперь генератор вычисляется из наблюдаемой ситуации (см. выше), а Balance Lab ничего не передаёт. Оценочная функция и поиск не менялись. Изменение лишь по-другому выбирает *одну случайную раскладку неизвестной колоды* на ход, поэтому метрики сдвинулись в пределах шума (200 походов, seed 42–241):

| | до | после |
|---|---:|---:|
| Ходов за поход | 9,17 | 9,18 |
| Связок за ход | 0,75 | 0,75 |
| Карт за ход | 2,24 | 2,23 |
| Использование маны | 94,3% | 94,1% |
| Здоровье Бранн / Лира | 19,7 / 13,3 | 19,5 / 13,4 |
| Узлов поиска на ход (макс.) | 58 (167) | 58 (160) |

Три классические стратегии не затронуты: 195/200, 200/200, 200/200 и 10,39 / 13,63 / 11,86 хода.

JSON-отчёт (`schemaVersion: 2`) содержит сводку, время по стратегиям и записи всех проходов, включая `planning` (узлы поиска).
