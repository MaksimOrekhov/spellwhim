# Spellwhim — проектные инструкции

## О проекте

Spellwhim — личная фанатская PvE-карточная roguelike-игра во вселенной Warcraft. Художественное направление — яркое, выразительное stylized hand-painted fantasy с добродушным юмором, вдохновлённое общим настроением карточных приключений Hearthstone. Первый сюжетный эпизод — альтернативная таверновая история в классических Мёртвых копях с Варианом Ринном и Джайной Праудмур. Текущая боевая пара — Вариан Ринн (Воин, внутренний ID `warrior`) и Джайна Праудмур (Маг, внутренний ID `mage`). Идентификаторы классов остаются совместимыми до отдельной реализации Party System.

Основной стек: Vue 3 Composition API, `<script setup lang="ts">`, TypeScript, Vite, PixiJS 8 для боевых эффектов, Tauri 2 для настольной оболочки и Vitest для правил боя. Интерфейс игры и карты строятся Vue/HTML/CSS; PixiJS отвечает за частицы, снаряды, вспышки и эффекты попадания. Сохраняй это разделение, если нет конкретной причины его менять.

## Игровая логика

- Правила и начальное состояние хранятся в `src/game/battle.ts`. Не помещай правила боя в компоненты.
- Типы и определения карт находятся в `src/game/types.ts`.
- `BattleState` содержит все зоны колоды, RNG, ману, здоровье, временные состояния и один `pending`-розыгрыш. `useBattle.ts` клонирует состояние, вызывает правила и публикует результат через `shallowRef`.
- `CardDefinition` — шаблон с классом, тегами и массивом `effects`; `CardInstance` — конкретная копия с уникальным `instanceId` и ссылкой `definitionId`. Все клики, ключи Vue и перемещения используют `instanceId`.
- **Историческая модель (до X04), контроль Balance Lab и эталонов:** стартовая колода `startingDeck` — 18 карт, по две копии девяти стартовых способностей (`types.ts`); основная игра начинает с `honestDeck('armor8', true)` (см. B2 Long ниже). Начальная рука — 8 карт, предел — 10. В контрольной экономике B мана растёт 3→4→5 и каждый ход полностью восстанавливается; прогрессия начинается заново в каждом бою, остаток не переносится. Несыгранные карты сохраняются; добор — 2 карты в начале ходов 2–4 и 3 с хода 5. Заблокированные лимитом карты остаются в колоде.
- Balance Lab (`balance.ts`) и бот-планировщик (`balancePlanner.ts`) играют только через `createBattle`, `playCard` и `endTurn`; планировщик не должен читать порядок колоды, `rngState`, `seed`, идентификаторы экземпляров карт или будущие действия врага: его случайная раскладка неизвестной колоды считается только из наблюдаемой ситуации (тесты это проверяют, в том числе через стратегию `planner`); каталог `research/mana/` — изолированный снимок исследования экономики маны, игра его не импортирует. Не копируй правила в бота — вызывай движок. Стратегии `aggressive`/`defensive`/`balanced` остаются контрольными; их числа менять нельзя без осознанного пересмотра отчёта.
- Видимость намерения врага определяется одной политикой — `src/game/observableIntent.ts` (`publicIntent`, `visibleThreat`): при подготовке игрок и боты знают цель и тип удара, но не его размер; раскрытый удар известен точно. Боты (`chooseCard(state, strategy, information = 'public')`, сценарии) читают угрозу только через неё; `'omniscient'` — историческая диагностика (эталон 427 боёв, воспроизведение старых отчётов), все отчёты до Fair Bot Information получены ею. Подробности — `docs/fair-bot-information-v01.md`.
- Все эффекты добора используют `drawCards` и соблюдают общий предел руки. Не влезающие в руку карты остаются в колоде; `blockedDraws` считает заблокированные попытки добора для Balance Lab.
- `startCardPlay` проверяет руку, ману и завершённость боя, оплачивает карту и переносит одну копию в `pending`. `resolveCardPlay(actionId)` однократно применяет зафиксированный план. Повторные/устаревшие ID ничего не меняют; пока есть `pending`, другие карты и конец хода запрещены.
- Для сценариев используйте атомарный `playCard(state, instanceId)`. Не вызывайте отдельные эффекты из Vue. `previewCard` рассчитывает усиление теми же правилами без мутации.
- Розыгрыш попадает в сброс после своего добора, поэтому не может добрать сам себя в процессе разрешения. Реально вернувшуюся из сброса платную карту можно снова оплатить и сыграть. Бесплатный Быстрый выпад выбывает до конца боя (`exhausted`).
- `Уязвимость` — статус из общего реестра `statuses.ts`; хранится в `BattleState.statuses.enemy` (у героев те же списки `statuses.warrior`/`statuses.mage`, в игре они пока пусты), сохраняется между ходами и не суммируется. Поля `enemy.vulnerable` нет. Новые статусы добавляются записью в `statusDefinitions` (поля `hitBonus`/`tick`), а не новой переменной; подробности и пример — `docs/status-foundation-v01.md`. Следующая карта с фактически выполняемым эффектом урона получает +3 до поглощения урона бронёй врага и расходует эффект, даже если броня поглотила весь удар. Не наносящий урона розыгрыш и неактивный условный урон не расходуют состояние. При одновременном использовании и наложении сначала применяется старый заряд, а новый остаётся только если враг выжил. Любой класс может использовать эффект; наложение не связано с классом.
- `Кровотечение` (`bleeding`, Combat Overhaul v0.2) — второй статус реестра: у врага, сила `N` складывается при повторном наложении до 5; в начале хода врага (`runEnemyTurnStart`, до его действия) он теряет `N` здоровья через `damageEnemy` (броня не поглощает), затем сила −1, на нуле статус исчезает. Тик может убить врага до действия и сдвигает его во вторую фазу тем же порогом, что и урон карты (объявленное действие всё равно исполняется, новый шаблон начинается после него). Карты — только в наградах: «Рассекающий удар» (5 урона + Кровотечение 3), «Кровавая расплата» (`status-burst`: +2 урона за каждую силу и снятие всего статуса — будущих тиков нет) и «Жар в венах» Мага (`status-tick`: тот же тик сразу, плюс добор; общий урон Кровотечения не растёт). Эффекты `status-burst`/`status-tick` читают только состояние статуса; ничего не привязано к классу или герою. Стартовая колода не менялась (решение и цифры — `docs/combat-overhaul-v02.md`).
- Классовые условия карт (бонус от брони владельца, адресная защита `class:<id>`) определяют участника отряда через `party.ts`: владелец — единственный участник с `classId` карты; если такого нет или их двое, условие не применяется, героя молча не выбирают. Не привязывай новые правила к `'warrior'`/`'mage'`, именам персонажей или паре Вариан + Джайна.
- Урон считается одной цепочкой (`damage.ts`): база → условие класса → статусы → артефакты → уменьшения, затем `splitDamage` (броня → здоровье). Предпросмотр карты, розыгрыш, прогноз врага и исполнение его атаки используют её же; враг теряет здоровье только через `damageEnemy`. Не добавляй отдельных формул в компоненты и в `resolveCardPlay`.
- Ледяная стрела и Удар щитом накладывают Уязвимость; остальные карты не получают это свойство автоматически. Ледяная стрела и Грозовой разряд получают +2 урона, пока у Джайны есть броня. Броня не расходуется; бонусы Уязвимости и брони Джайны складываются и отображаются отдельно в предпросмотре.
- Эффект называется «Уязвимость», короткая подпись — «Уязвим». Подсказка: «Следующая наносящая урон карта получает +3 урона и снимает Уязвимость». Иконка — универсальная мишень/слабая точка, без обязательной ассоциации с бронёй или конкретным классом.
- Броня поглощает урон без лечения и исчезает после следующей атаки по владельцу. Броня напарника от Бастиона сохраняется до атаки по нему (при текущем чередовании целей — до следующего хода врага). Между боями броня и состояния очищаются.
- Поход строится чистыми функциями из `campaign.ts`: шесть слоёв карты и финальный узел, три колонки, только прямые переходы. `DungeonRunState` хранит seed, карту, текущий/посещённый/завершённый узлы, колоду, здоровье героев и исход. Seed карты, встречи и награды выводятся независимо от выбора маршрута. Все пути достижимы, без тупиков, не менее четырёх боёв с финалом и не более двух элит.
- Закрытые и доступные узлы карты показывают только категорию («Обычный бой», «Элитный бой», «Привал», «Босс»), слой и состояние прохождения. Не выводи имя врага, HP, поведение или точный размер награды через текст, `title`, tooltip, `aria-label` или иное представление карты. Конкретная встреча уже зафиксирована seed-ом и раскрывается после входа в бой.
- Обычная победа предлагает выбор из трёх карт; элита — из пяти. Привал восстанавливает до 6 HP выбранному герою; здоровье и колода сохраняются между боями, броня и боевые состояния очищаются. Поражение завершает поход, победа завершается на финальном узле. `battle.ts` и модель экономики B остаются общими для всех встреч.
- Поведение противников задаётся небольшими детерминированными последовательностями `phase1`/`phase2` в `types.ts`. `BattleState.enemy.nextAction` — единственное объявленное и исполняемое действие; подготовленная атака сохраняет цель в самом действии. Переход босса во вторую фазу на половине здоровья оставляет текущее намерение неизменным и начинает новый паттерн после его выполнения.
- Броня противника поглощает урон карт до здоровья и ограничена 8 очками, чтобы циклы защиты не создавали неразрушимый запас. `CardPreview` показывает общий урон, урон по броне и здоровью отдельно.
- Атака по отряду вычисляет прогноз обоих попаданий до применения и использует один снимок брони/здоровья. Основная цель обозначается действием; обычная стойка прикрывает её, Бастион также даёт броню напарнику.
- Вариан начинает с 25 здоровья, Джайна — с 18. Смерть любого героя завершает бой поражением; ноль здоровья врага — победой. После смертельного эффекта последующие эффекты карты и добор нового хода не выполняются.
- Перемешивание использует Mulberry32 и `rngState` в состоянии. `createBattle` принимает seed, состав колоды и размер стартовой руки; одинаковые параметры и действия воспроизводят весь бой. В UI seed выбирается при запуске похода.
- Состояние боя — единственный источник истины. Не меняй здоровье, ману или результат отдельно в UI.
- Подсказки, справка и подписи кнопок обязаны совпадать с движком и фактическим действием (аудит `docs/reviews/ux-consistency-legacy-audit-v1.md`, тесты `src/ui/uxAudit.test.ts`). Тексты, зависящие от правил (рука, мана, срок брони, свойства ударов), берут данные из `useRules()`, а не из литералов; при расхождении сначала найди источник истины в `battle.ts`, не маскируй дефект движка текстом.
- Враги подземелья задаются **ростером** (`rosters.ts`: `DungeonRoster` — каталоги, пулы слоёв, масштаб здоровья по позиции, финал). Игра использует `defaultDungeonRoster` = `rosterV10` (`encountersV10.ts`); `rosterV09` (`encountersV09.ts`) — контроль, ничем не меняется; экспериментальные A–E — `encounterExperiments.ts`. `createDungeonMap`/`dungeonEncounter`/`createDungeonRun`/`validateDungeonMap` принимают ростер последним аргументом. Одному seed соответствует одна карта в любом ростере. Эталон 427 боёв (`statusFoundation.regression`) использует каталоги v0.9 и остаётся контролем прежних правил.
- Экономика (`economy.ts`) — единственное описание кривой маны, расписания добора и пакета врагов; `battle.ts` применяет её (`createBattle({ economy })`, `endTurn`), `BattleState.economy` хранит её данные. До X04 стандартная игра использовала `gameEconomy` (B: кривая 3→4→5, добор late3, враги v0.7) во всех сборках и при рестарте. `baselineEconomy` (A: v0.6) остаётся контрольной экономикой Balance Lab; новые поля отчётов нормализуются перед сравнением старых показателей. U остаётся экспериментальной, доступной для Balance Lab и dev-сравнения (`?economy=U`; `?economy=A` выбирает контроль).
- **Основная игра — B2 Long (Decision Log X04, `docs/design/default-b2-long-v1.md`).** Обычный запуск в любой сборке (dev, production, Tauri) играет `defaultRulesMode` = `honest-b2-long` (рука 7 со сбросом, мана 4, броня на ход врага, циклы B1, Обморожение, колода armor8 + мороз, десять посещений) в слоте `spellwhim.run.v1.honest-b2-long`; внутренние идентификаторы, экономика и версии сохранений **не переименовывать** — старые сохранения читаются без миграции. Что играет страница, решает только `resolveLaunch(search, import.meta.env.DEV)` в `rulesMode.ts`: другие режимы (A08/A09, B1, B2, long, контроль) открываются лишь в dev-сборке явным `?dev-rules=<id>` (там же работают `&deck=`, `&seed=`, `&economy=` и бейдж «Лаборатория»); старые `?rules=`, `?deck=`, `?seed=`, `?economy=` обычную игру не меняют. Меню не показывает правил, колод и внутренних обозначений (A, B1, B2, «эксперимент»). Слоты сохранений других режимов не читать, не перезаписывать и не удалять. `gameEconomy` — контрольная модель Balance Lab и эталонов, не игровая. Ниже «включается только явно (`?rules=…`)» в описаниях экспериментов теперь читается как `?dev-rules=…` в dev-сборке.
- **EXPERIMENT «Честный ход A»** (`honestEconomies` в `economy.ts`, `rulesMode.ts`, `docs/design/honest-turn-a-experiment-v1.md`, Decision Log X01): рука 7 со сбросом, мана 4, броня до конца хода врага, враги ×1,75 здоровья и ×0,8/×0,9 урона. Включается только явно (`?rules=honest-a08|honest-a09` или переключатель на стартовом экране), хранит поход в своём слоте сохранений и **не меняет** `gameEconomy`. Его поля (`discardHand`, `armorExpiry`, `enemyDamageScale`, `excludedArtifacts`) не добавляй в экономики A/B/U: они должны оставаться байт-в-байт прежними ради сохранений. Правила эксперимента не утверждены GDD.
- **EXPERIMENT «Честный ход B1/B2»** (`sectorFoesB.ts`, `honestDecks.ts`, `honestLab.ts`, `docs/design/honest-turn-b-experiment-v1.md`, Decision Log X02): те же правила A (рука 7, мана 4, сброс, броня на ход врага), но шесть врагов сектора I живут по новым циклам (B1: бронебой `pierce`, срыв удара `interrupt`, метка `exposes`, ярость `power`, вторая фаза Рак'Зора с `phaseNote`), а B2 добавляет статус `Обморожение` (`frostbite`) и две экспериментальные карты («Ледяная хватка», «Раскол льда»). Включаются только явно (`?rules=honest-b1|honest-b2`, `&deck=armor10|armor8|armor6`, переключатель на стартовом экране), у каждого свой слот сохранений и версия правил. Все свойства ударов — **необязательные поля** `EnemyHit`/`EnemyAction` и `EnemyState`: у стандартных врагов их нет, объявленное намерение исполняется ровно так, как показано (срыв и ярость не меняют уже объявленное действие, а отменяют/усиливают исполнение или следующие объявления по правилу, показанному заранее). Экспериментальные карты лежат в `experimentalCards`, **не** в `cards` (отпечаток каталога сохранений, награды и проверки «все карты» остаются прежними). Не добавляй эти поля в `gameEconomy`, `baselineEconomy` и `playableEconomies`.
- **EXPERIMENT «Длинный сектор I»** (`sectorLong.ts`, `scripts/run-sector-long*.mjs`, `docs/design/sector-one-long-v1.md`, Decision Log X03): девять рядов и босс (10 посещений), 4–5 обычных боёв, необязательная элита, привал перед боссом; три дополнительных врага (`longSectorEnemies`) на свойствах ударов B1. Режимы `?rules=honest-b1-long|honest-b2-long` (экономика = B1/B2 + необязательное поле `sectorRoute: 'long'`), свой слот сохранений, `rulesVersion` `honest-turn-b*-long-1` и свой `LONG_SECTOR_CATALOG_VERSION`. Короткий сектор не меняется: `sectorEncounters`/`SECTOR_CATALOG_VERSION` прежние, генератор для `sectorOneConfig` даёт те же карты (тест хранит дайджест 400 карт). Новые враги и конфиг ищи в `knownSectorEncounters`, а не в `sectorEncounters`. Карта из десяти рядов рисуется компактно (`CampaignMap`, `is-dense`) и прокручивается к отряду.
- **Выбор получателя брони** (`armorChoice`, `armorFocusOf` в `battle.ts`, `ArmorChoiceDialog.vue`, `docs/armor-target-choice.md`): карты с бронёй «цели врага»/«напарнику» (`threatened`/`partner`) против удара **по обоим героям** (в том числе подготовленного) спрашивают, кто основная цель; против одиночного удара выбор не предлагается и решает движок. Выбор — необязательный параметр `previewCard`/`startCardPlay`/`playCard` и поле `PendingPlay.armorFocus` (у розыгрыша без выбора ключа нет). Прогноз потерь берётся из настоящих `previewCard` и `forecastEnemyAction`; не считай его отдельно в компонентах.
- Новые карты добавляй данными в `types.ts`, затем подключай нужную игровую операцию, арт, презентацию эффекта и тесты. Не копируй большие фрагменты карточного компонента.

## Компоненты и анимации

- Данные передаются вниз через props, действия — вверх через typed emits.
- `App.vue` связывает игровое состояние с представлением, а не содержит разметку всех секций сцены.
- Для новых PixiJS-анимаций корректно удаляй ticker callbacks и display objects. При размонтировании отключай `ResizeObserver`, останавливай ticker и уничтожай приложение и canvas.
- Эффекты должны ясно показывать источник, цель и момент попадания. Меч — короткий световой росчерк у противника; огненный шар — заметный снаряд от руки к противнику с вспышкой; защитные действия Вариана показывай через стойку, блок Шаламейном или прикрытие напарника, а срабатывание Уязвимости — отдельным универсальным индикатором у противника. Атака стража вызывает реакцию именно выбранного героя.
- **Боевые эффекты (Combat Feel & VFX v1, `docs/design/combat-feel-vfx-v1.md`).** Вид эффекта выбирается по тому, что движок решил (`PendingPlay.preview`/`effects`/`consumedStatuses`, `forecastEnemyAction`), а не по `card.kind`: `cardVfxPlan`/`enemyVfxPlan` в `src/vfx/plan.ts` строят чистый `VfxPlan` (биты со временем, один `impactMs`, `reaction`), `useBattleAnimation` кладёт его в `animation.vfx`, `BattleFx` рисует. Бит эффекта существует только если событие реально произошло; числа и статусы берутся из превью/прогноза, правил в `src/vfx` нет. План подготовленной атаки строится только из `publicIntent` (цель и «что-то готовится»): не читай `futureTargets`/`.prepared` в эффектах. Вид новой карты — запись в `src/vfx/cardStyles.ts` (`Record<CardId, …>`). Painters рисуют только через `FxRuntime` (один ticker, три слоя, пул частиц с лимитом); новых `Graphics` и ticker-колбэков на эффект не создавай. Reduced motion — `plan.motion` (`motion.ts`), поддерживай его в каждом новом painter. Проверка вручную: `card-preview.html?view=vfx&fx=<сцена>`, стоп-кадры `scripts/vfx-shots.mjs`, проверка ресурсов `scripts/vfx-check.mjs`.
- `BattleFx` и fallback передают ID анимационного действия; `useBattleAnimation` принимает только текущий ID и очищает таймеры при смене сцены/размонтировании. Pixi ticker callbacks и отложенные вспышки очищаются при новом действии.
- **Ambient VFX & Audio v1** (`docs/design/ambient-vfx-audio-v1.md`): атмосфера живёт отдельно от боевого Pixi ticker, максимум 26 CSS-частиц за ареной, без отдельного canvas; hidden/reduced motion останавливают движение. `audio/cues.ts` переводит только готовый VfxPlan в звуки, `runPlan` ставит их на общие часы; игровое действие от звука не зависит. `audio/engine.ts` — один ленивый Web Audio context после trusted ввода, лимит 16 источников, mute/hidden/выход очищают источники и атмосферный таймер; настройки отдельно в `spellwhim.audio.v1`, не в сохранении похода. Лаборатория VFX поддерживает отдельное прослушивание тембров и четыре атмосферных профиля; проверка — `scripts/ambient-audio-check.mjs`.
- **Audio Asset Discovery & Sound Library v1** (`docs/design/audio-asset-discovery-v1.md`): `audio-preview.html` и `src/components/AudioLibrary.vue` — отдельная dev-библиотека аудиокандидатов, не production-интеграция. `docs/audio/candidates.json` — машинный каталог, `docs/audio/ASSET_LICENSES.md` — источники, лицензии и измеренные характеристики; `npm run audio:catalog:check` проверяет файлы и метаданные, `npm run audio:library:check` — воспроизведение и поведение библиотеки в браузере.
- Основная визуальная и производительная цель текущего этапа — персональная полноэкранная игра на основном мониторе 2560×1440; 1920×1080 — дополнительная проверка. Не добавляй специальные режимы частиц, CSS и геометрию ради маленьких окон; существующую адаптивность и автоматические проверки сохраняй.
- Не блокируй действия игрока дольше визуальной анимации. Недоступность карты должна объясняться стоимостью маны или состоянием «Сыграна».
- Держи текстовые подписи читаемыми и разнесёнными: здоровье не должно закрывать имя персонажа, а плашки хода и журнал — карты или портреты.

## Иллюстрации и визуальный стиль

- Для любого нового контента сверяйся с `ART_BIBLE.md` и `LORE_BIBLE.md`. Spellwhim использует узнаваемых канонических персонажей Warcraft; визуальный ориентир — тёмноволосый Вариан в сине-золотых доспехах с Шаламейном и классическая Джайна с золотисто-светлыми волосами до уничтожения Терамора. Перед добавлением существенных лорных фактов проверяй их по официальным материалам Blizzard и проверяемым справочникам Warcraft. Разделяй канон и альтернативные события Spellwhim. Юмор уместен, пока сохраняет характер персонажей. Новые герои, классы, противники и подземелья должны соответствовать зафиксированной концепции; существенные изменения художественного направления сначала согласуй с пользователем.
- Перед созданием карт, классовых эмблем, палитр или изменением оформления карт сверяйся с `CARD_DESIGN_SYSTEM.md`. Цвета и идентичность классов хранятся в `src/game/classThemes.ts`; не дублируй цветовые значения в компонентах. Класс карты независим от героя и должен оставаться узнаваемым без персонажа внутри иллюстрации.
- Все игровые иллюстрации хранятся в `src/assets/art/`. Имена файлов — краткие `kebab-case`.
- Текущий формат — квадратные JPEG примерно 768×768. Стремись к качественным, но компактным ресурсам; оптимизируй до добавления в проект.
- Портреты показываются в круглой рамке. Помещай лицо/главную деталь близко к центру и оставляй безопасное поле по краям, чтобы круговое кадрирование не отрезало важное. Не добавляй в сами файлы рамки, овалы, интерфейс или подписи: форма и обводка создаются CSS.
- Арты карт показываются в почти квадратном окне карты. Держи действие крупным, узнаваемым в небольшом размере и внутри центральной части кадра. Карточный текст и декоративная рамка — отдельная HTML/CSS-разметка.
- Единый стиль: яркое, выразительное, немного комичное фэнтези с живописной фактурой, выразительными формами и насыщенным светом; не dark fantasy, не аниме и не фотореализм. Узнаваемые персонажи и места должны сочетаться по палитре и освещению.
- Для классов сохраняй визуальные сигналы: воин — сталь, бронза, янтарный свет и физические защитные приёмы; маг — аметист, тёмно-синий и золотое свечение; защита — стойка, блок или прикрытие союзника; огонь — яркий оранжево-золотой с фиолетовым магическим акцентом. Не изображай Вариана создающим магические щиты; значок Уязвимости универсален и не должен выглядеть как обязательное разрушение брони.
- Создавай оригинальные фанатские иллюстрации, сверяясь с официальными референсами ради канонических черт и предметов. Не вставляй извлечённые игровые изображения, логотипы, звуки или модели Blizzard; не копируй конкретные иллюстрации, композиции, рамки карт или интерфейс Hearthstone. Если добавляется внешний ресурс, сначала проверь лицензию и укажи происхождение в README.
- Для подключения импортируй файл явно в компонент, который его использует. Не обращайся к изображениям из случайного абсолютного пути или из каталога генерации вне проекта.

## Дизайн-токены и типографика

- Цвета, материалы (градиенты), шрифты, радиусы, тени, кромки, движение и отступы определены в `src/assets/tokens.css`. Компоненты ссылаются на токены; новый литеральный цвет, радиус или тень в компоненте — признак недостающего токена. Старые компоненты переводятся на токены по мере переписывания (этапы редизайна), массовой замены не делай.
- Цвета классов живут только в `src/game/classThemes.ts` (`classThemeStyle` → `--class-*`) и в токены не копируются.
- Шрифты — только локальные (`src/assets/fonts/`, woff2, кириллица + латиница), все под SIL OFL; никаких CDN и `@import` из сети. Семейства: **El Messiri** — заголовки, названия, ленты (`--font-display`); **Nunito** — интерфейсный текст (`--font-ui`); **Rubik** — цифры маны, здоровья, урона (`--font-num`). Не задавай `font-family` литералом: используй `var(--font-*)`; для canvas/Pixi — `fontFamily('--font-display')` из `src/ui/typography.ts`. Новый шрифт: проверь кириллицу и лицензию, положи текст лицензии в `LICENSES/`, добавь запись в `docs/third-party-assets.md`; `fonts.test.ts` не пропустит неописанные файлы и семейства без лицензии.
- **Мягкие формы — принцип системы.** Никаких острых углов и `clip-path: polygon` на рамках, кнопках и панелях. Радиусы берутся из `--r-*` и `--shape-*` (крупные эллиптические радиусы с небольшой асимметрией); кнопка — «доска» с видимой толщиной (`.game-button`). Радиусы мельче `--r-1` на интерактивных элементах не допускаются.
- Новые UI-иконки — только Lucide (см. правило выше).

## Интерфейс и адаптивность

- Основной формат сцены — 16:9; проверяй компоновку на 1280×720, 1920×1080 и 2560×1440, а также на узких окнах.
- Сохраняй атмосферу фэнтезийной игры: не заменяй оформление на стандартные веб-панели или минималистичные прямоугольники.
- **Интерфейсные SVG-иконки нельзя генерировать нейросетью с нуля или рисовать вручную.** Используй готовые иконки из проверенных бесплатных open-source библиотек. Предпочитай одну согласованную библиотеку; в Spellwhim для новых UI-иконок используется Lucide через локально установленный `@lucide/vue`, без CDN. Перед добавлением сверяй лицензию и возможность распространения с игрой, сохраняй необходимые notices и записывай источник/лицензию в документацию проекта. Допускается менять размер, цвет и толщину линий параметрами библиотеки или CSS. Если подходящей иконки нет, найди её в другой библиотеке; не генерируй случайную SVG-иконку. Это ограничение касается UI-иконок, но не SVG-маршрутов, программных визуализаций и художественных иллюстраций. Не выполняй массовую миграцию старых текстовых/Unicode значков без отдельной задачи.
- Будущую категорию карты «?» для неизвестных событий вводи только вместе с работающей механикой событий и реальными вариантами исходов; не добавляй фиктивный узел-заглушку.
- Все игровые надписи интерфейса — на русском. Критическая информация (здоровье, мана, цель врага, доступность карты, чей ход) должна быть заметнее декоративных подписей.
- Все новые игровые имена, названия встреч, поведенческие заголовки, имена действий и подписи карты локализуй на естественный русский язык. Проверяй новые строки на опечатки, грамматику и понятность; не оставляй транслитерацию или механические формулировки там, где уместнее короткое тематическое название. Стабильные внутренние ID и числовые параметры не меняй ради локализации.
- При корректировке размеров текста проверь, что строки не пересекаются с портретами, картами, здоровьем или кнопкой завершения хода.

## Работа с Git

- **Основной каталог `spellwhim` — единственная рабочая копия проекта по умолчанию, и для Claude, и для Codex:** работа идёт в обычных ветках от актуального `origin/main`. Не создавай отдельный Git worktree для каждой задачи; предпочитай переиспользование существующего каталога и обычное переключение веток. Дополнительный worktree допускается только при обоснованной необходимости параллельной работы и **после разрешения владельца**.
- Перед началом: `git status`, текущая ветка, актуальность `origin/main` (`git fetch origin`).
- Новую рабочую ветку создавай от актуального `origin/main` в основном каталоге.
- **Перед каждым переключением ветки** проверяй `git status` (изменённые, неотслеживаемые файлы). Если там есть незакоммиченные изменения или переключение может затронуть файлы владельца — **остановись и сообщи**, не переключайся автоматически.
- По завершении коммить и пушь рабочую ветку. Слияние с `main` — только по отдельному согласованию.
- Не используй `git reset --hard`, `git clean -fd`, принудительное удаление worktree (`--force`) и другие разрушительные команды. Лишние worktree удаляются штатной `git worktree remove` и только после проверки, что в них нет незакоммиченных/неотслеживаемых файлов и вся работа сохранена в Git; worktree, чья ветка ещё не включена в `origin/main`, не удаляй — сообщи, какие коммиты остаются вне основной ветки. Ничего не сливай автоматически; ветки и историю не удаляй. Файлы, которых нет в Git (в том числе игнорируемые отчёты вроде `balance-reports/`), перед удалением каталога сохрани или спроси владельца; найденную незавершённую работу не удаляй без согласования.

## Команды

```bash
npm run dev       # браузерный режим
npm test          # тесты правил
npm run scenarios -- 42 # сценарии без UI с seed 42
npm run challenge:lab -- --runs 100 --seed 42 --rosters A,E --cards base,bleed,swap # Combat Challenge: полные походы, настоящие награды и артефакты
```
